# 3.3 延迟与吞吐加速比分析报告

## 1. 结论摘要

| 指标 | vdot.vv（单指令） | 基线组合 | 加速比 |
|---|---|---|---|
| **延迟**（同 vd 依赖链） | 7.0 周期/op（e8/e16/e32） | 7.0~7.1 周期/op | ≈1.0×（打平） |
| **吞吐**（独立 vd 流水） | **1.78 周期/op**（e8/e16/e32） | e8/e16：7.1 周期/op；e32：2.7 周期/op | **≈4.0×（e8/e16）/ ≈1.5×（e32）** |

- **延迟维度**：单条 vdot.vv 与 3~4 条指令的基线组合在"同目标寄存器依赖链"下延迟相当（都被向量写回等待时间支配），但 vdot 以 **1 条指令**完成同等计算，指令数、发射端口占用、代码密度大幅优于基线。
- **吞吐维度**：vdot 单指令流水化执行（设计 latency=2、piped=true），达到 **1.78 周期/op 的背靠背吞吐**；基线 e8/e16 每个点积需 vsetvli 切换 + vwmul + vwredsum 共 4 条指令串行依赖，吞吐仅 ~7.1 周期/op；**vdot 吞吐加速约 4 倍**。基线 e32 无 vsetvli 切换（2 条指令），吞吐 2.7 周期/op，vdot 仍快约 1.5 倍。

## 2. 测量方法

采用 ChatGPT 建议并经确认的 **B 主 + A 辅** 方案：

- **B（主）周期计数**：在 AM（nexus-am）裸机环境用 `rdcycle` 对每个 kernel 计时，循环 N 次取最小（run3），扣除空循环 overhead，按 `C(N) = a + b·N` 线性拟合，**取斜率 b 为单条指令周期数**（消除固定开销）。
- 每 kernel 独立程序单独运行（见 §5 死锁/异常调查），N 取 10 / 100 / 500 三档验证线性。
- **A（辅）波形**：波形证据（vdot 单次写回 vs 基线两次写回）见 §6。
- 环境：MinimalConfig，VLEN=128，`--no-diff`（纯 RTL 时序），运行前 `enable_vs()` 使能向量扩展，并在 AM 启动代码加入 `csrw mcounteren, -1`（默认复位全 0 会屏蔽 S 模式 `rdcycle`）。

## 4. 分析

### 4.1 延迟（Latency，同 vd 依赖链）

- vdot_lat：每条 vdot 写回 v2，下一条 vdot 读 v2 → 严格依赖链，实测 **7.0 周期/op**（e8/e16/e32 一致，与元素位宽无关——延迟受 vd 写回与发射等待支配）。
- base_lat：vwmul→vwredsum 依赖链 + vsetvli 切换，实测 **7.0~7.1 周期/op**。
- **结论**：单指令 vdot 的延迟链与基线组合相当；但基线每 op 需 3~4 条指令、2 次 vsetvli，在**发射带宽与指令缓存**上开销大，vdot 以 1 条指令达到同等延迟水平。

### 4.2 吞吐（Throughput，独立 vd 流水）

- vdot_thr：4 个独立累加器（v4~v7）轮换，vdot 单指令流水化（latency=2、piped=true）背靠背发射，实测 **1.78 周期/op**（≈ 2 周期 = 流水级数，与设计 latency=2 吻合）。
- base_thr：
  - e8/e16：每 op = vsetvli(m1) + vwmul + vsetvli(m2) + vwredsum 共 **4 条指令串行依赖**，实测 **7.1 周期/op**。
  - e32：vmul + vredsum 2 条指令、无 vsetvli 切换，实测 2.7 周期/op。
- **结论**：vdot 吞吐较基线 e8/e16 快 **约 4 倍**（7.1/1.78 ≈ 3.99），较基线 e32 快 **约 1.5 倍**（2.7/1.78 ≈ 1.52）。加速主要来自：①单指令消除 vsetvli 切换与指令间依赖；②融合乘-累加（fused multiply-accumulate）流水化。

### 4.3 加速比汇总

| 场景 | vdot（周期/op） | 基线（周期/op） | 加速比 |
|---|---|---|---|
| Latency e8 | 7.0 | 7.1 | 1.01× |
| Latency e16 | 7.0 | 7.1 | 1.01× |
| Latency e32 | 7.0 | 7.0 | 1.00× |
| Throughput e8 | 1.78 | 7.1 | **3.99×** |
| Throughput e16 | 1.78 | 7.1 | **3.99×** |
| Throughput e32 | 1.78 | 2.7 | **1.52×** |

## 5. 测量工程记录（死锁/异常调查）

### 5.1 完整 benchmark 单进程卡死 → 改为每 kernel 独立程序

- 现象：12 kernel × 3 档 N 的完整单进程程序 4/4 次运行必然卡死，卡点随机（e16,1000 / e32,1000 / e32,500 / vdot_lat_e32,100），但任一 kernel 单独运行均正常。
- 证据：`--dump-commit-trace` 显示卡死时 PC 严格循环 vdot→addi→bne，vdot 持续正常 commit 且 v2 正确累计（每周期 +0x88=136），最终停在某次 vdot 写回后不再推进 —— **RTL 写回路径偶发 stall（真 stall，difftest 无 mismatch），非程序错误、非确定性**。
- 处理：改用**每 kernel 独立程序**采集（12 个程序各测 1 kernel × 3 档 N），全部正常结束；数据口径与完整程序一致（同 kernel、同 N、同计时）。
- 说明：该问题为 MinimalConfig 下 vdot 写回路径与长依赖链组合的偶发 RTL stall，3.3 测量采用独立进程规避，不影响结论（单 kernel 数据可复现、可复核）。

### 5.2 base_thr_e8 卡死 → vwmul LMUL 非法指令（double trap）

- 现象：base_thr_e8 独立程序在 ~4758 周期、第 605 条指令处停止，`--dump-commit-trace` 报 `HIT CRITICAL ERROR: double trap`（GOOD TRAP at pc=0xe）。
- 定位：反汇编 + commit trace 对照，卡在循环内**第 2 个 `vwmul.vv`** —— 该指令在 `vsetvli e16, m2` 状态下执行。
- 根因：`vwmul.vv` 是宽乘（widening），**输出 LMUL = 2×输入 LMUL**。e16 m2 输入 → e32 m4 输出，输出寄存器组 v2-v5 覆盖累加器 v4/v5，且该 LMUL 组合触发香山 RTL 非法指令异常 → 异常向量处再次异常 → double trap。
- 修复：每个 `vwmul.vv` 前强制 `vsetvli` 回 e8/e16 m1（与 3.2 已通过的 baseline 模式一致），每个 `vwredsum.vs` 前切到 e16/e32 m2。修复后 3 个 base_thr 全部正常。
- 注：base_lat_* 循环每轮尾部切回 m1，故从未触发该问题。

### 5.3 环境补丁

- AM 启动代码 `nexus-am/am/src/nemu/isa/riscv/boot/start.S` 在 `_start:` 后加入 `li a0, -1; csrw mcounteren, a0`。原因：香山 `mcounteren` 复位全 0，S 模式 `rdcycle` 被屏蔽；本 benchmark 在 M 模式运行本无需，但为与 difftest/工具链一致保留。属环境改动，不影响仿真结果。

## 6. 写回证据：commit trace 指令级记录（A 辅）

**方法**：VCD 波形（`--dump-wave-full`，451~463MB，见 §6.2）已生成并保存，但香山 MinimalConfig 的 RTL 中向量写回路径分散于多条总线（`io_writeback_*` / `io_toCtrlBlock_writeback_*` / VRF `write_wen_*` 等），且大量复位/刷新信号产生噪声，直接从 VCD 提取"单次 vs 两次写回"需复杂的信号语义还原。因此采用**指令级 commit trace**（`--dump-commit-trace`，difftest 模式）作为等价且可直接审计的写回证据：**commit 是每条指令写回寄存器的唯一权威记录**（格式：`commit pc <地址> inst <编码> wen <写使能> dst <目标寄存器> data <写回数据>`）。

### 6.1 vdot.vv：1 条指令 = 1 次写回

来自 `logs/stage3/bench-ct2.log`（vdot 循环段，vdot_lat 依赖链，v2 逐次累计）：

```
[02] commit pc 000000008000023a inst 12103157 wen 1 dst 02 data 0000000000000088 idx 022
[05] commit pc 000000008000023a inst 12103157 wen 1 dst 02 data 0000000000000110 idx 025
[08] commit pc 000000008000023a inst 12103157 wen 1 dst 02 data 0000000000000198 idx 028
[11] commit pc 000000008000023a inst 12103157 wen 1 dst 02 data 0000000000000220 idx 02b
[14] commit pc 000000008000023a inst 12103157 wen 1 dst 02 data 00000000000002a8 idx 02e
```

- `inst 12103157` = vdot.vv v2, v0, v1（自定义编码）；
- 每次 commit 仅 **1 条指令**，`wen 1 dst 02` 单次写回 v2；
- `data` 依次为 0x88(136) → 0x110(272) → 0x198(408) … 每次 **+0x88**，与 e8 点积 1+2+…+16=136 的累加语义完全吻合，证明 vdot 单指令完成"乘+累加"并单次写回。

### 6.2 基线组合：2 条指令 = 2 次写回

来自 `logs/stage3/base_thr_ct.log`（base_thr_e8 循环段，同一次点积的相邻两条 commit）：

```
[27] commit pc 00000000800001c4 inst ee00a157 wen 1 dst 02 data 0004000300020001 idx 02b   ← vwmul.vv  v2, v0, v1
[29] commit pc 00000000800001cc inst c6220257 wen 1 dst 32 data 0000000800000006 idx 02d   ← vwredsum.vv v4（物理 32）
```

- `inst ee00a157` = vwmul.vv v2, v0, v1（funct6=111011），**第 1 次写回**（dst 02，中间乘积）；
- `inst c6220257` = vwredsum.vv（funct6=110001），**第 2 次写回**（dst 32 = v4 的物理寄存器，归约结果）；
- 每次点积基线需要 **2 条指令、2 次写回**（吞吐测法另含 2 次 vsetvli，共 4 条）。

### 6.3 对比结论

| 维度 | vdot.vv | 基线（vwmul+vwredsum） |
|---|---|---|
| 完成一次点积的指令数 | **1** | 2（吞吐场景再加 2 次 vsetvli = 4） |
| 向量写回次数 | **1**（dst v2） | **2**（dst v2 中间 + v4 最终） |
| 写回数据 | 单指令直接产出最终累加值（+0x88/次） | 需跨两条指令中间传递 |

指令级记录直接支撑 §1 结论：vdot 以**单指令单写回**完成基线**多指令多写回**的计算，是吞吐加速（1.78 vs 7.1 周期/op）的硬件根因。

### 6.4 VCD 波形存档与信号说明

- 波形文件已生成（未提交仓库，体积 451~463MB）：`--dump-wave-full` 下 VCD 含全部 35 万+ 信号声明（`wave1.vcd`）；`--dump-wave`（非 full）仅写头部不写正文，必须使用 `--dump-wave-full`。
- 向量写回信号族（供复核）：执行单元写回总线 `io_writeback_13..17/23..24_bits_vecWen`、`io_writeback_*_bits_pdest`；Rob 侧 `io_toCtrlBlock_writeback_*_bits_vecWen`；定点向量单元写回目标 `vFixPoint64b_io_fromAdder_vd_0..7`；VRF 写使能 `write_wen_<port>_<reg>`（注意区分复位/刷新噪声与真实指令写回）。
- 因上述信号在 MinimalConfig 下分散且含噪声，报告采用 commit trace 作为主写回证据；VCD 作为原始存档保留在本地，提取脚本见 `logs/stage3/`。

## 7. 结论

1. vdot.vv 以**单条指令**实现了基线 3~4 条指令组合（vsetvli+vwmul+vwredsum/vredsum）的点积功能。
2. **吞吐加速显著**：独立 vd 流水下 vdot 1.78 周期/op，较基线 e8/e16 快约 4 倍、e32 快约 1.5 倍。
3. **延迟相当**：依赖链下二者均受写回等待支配（~7 周期/op），但 vdot 指令数与发射占用仅为基线 1/3~1/4。
4. 测量过程暴露并记录了 MinimalConfig 下两个 RTL 边界问题（长依赖链写回偶发 stall、vwmul 高 LMUL 非法指令），均已绕过/规避，数据完整可复现。
