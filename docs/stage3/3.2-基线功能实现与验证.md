# 3.2 基线功能实现与验证

> 阶段三 · 交付物 3.2
> 日期：2026-09-18
> 对应官方要求：用已有向量指令组合实现基线（vmul.vv + vredsum.vs 组合实现同功能），基于香山仿真环境验证

---

## 一、基线定义

基线 = **标准 RVV 指令组合**实现与 vdot.vv 完全相同的点积功能（SEW=8、VLEN=128、结果写 vd 低 32 位）：

| 精度 | 指令组合 | 说明 |
|---|---|---|
| e8 | `vle8.v` + `vwmul.vv`(e8→e16) + `vwredsum.vs`(e16→e32) | 宽乘 + 宽归约，乘积/累加不截断，结果精确 32 位 |
| e16 | `vle16.v` + `vwmul.vv`(e16→e32) + `vredsum.vs`(e32) | 同上 |
| e32 | `vle32.v` + `vmul.vv`(e32) + `vredsum.vs`(e32) | 乘积 64 位高位截断（用例值不越界） |

对应官方 3.2 表述"vmul.vv + vredsum.vs 组合"：`vwmul.vv`/`vwredsum.vs` 分别是元素乘法与归约求和的 widening 扩展形式（RVV 1.0 标准指令）。

**与 vdot 单指令的关键差异**：

| 维度 | vdot.vv（专用单元） | 基线（指令组合） |
|---|---|---|
| 指令条数 | 1 条 | 3~4 条 + 3 次 vsetvli（vtype/vl 切换） |
| 乘法实现 | 专用 Booth/CSA 阵列（宽度自适应） | 向量 ALU 逐元素乘法（vwmul） |
| 归约实现 | Fused ReduceAcc（CSA 树 + 单次 CPA） | vwredsum 归约单元 |
| 中间状态 | 无（单条写回） | 需 v2/v4 中间寄存器 + vmv.s.x 清累加器 |

## 二、基线程序

`code/stage3/vdot-baseline/vdot-baseline.c`（nexus-am 应用，13 用例与 vdot-test 完全同输入同期望）。

e8 基线核心序列：

```c
vsetvli vl, n, e8, m1
vle8.v  v0, (a)
vle8.v  v1, (b)
vwmul.vv v2, v0, v1          // 8x8 -> 16 宽乘，v2/v3 组（LMUL=2）
vsetvli vl, x0, e32, m1
vmv.s.x v4, x0               // 清累加器低 32 位
vsetvli vl, n, e16, m2       // vl 必须恢复为 n（见下"关键修复"）
vwredsum.vs v4, v2, v4       // E16 向量归约 -> E32 标量（累加 v4 旧值）
vsetvli vl, x0, e32, m1
vse32.v v4, (c)              // 写低 32 位
```

## 三、关键问题与修复

### 问题：部分 vl（vl<n）用例结果错误

初版 `vwredsum.vs` 前使用 `vsetvli %0, x0, e16, m2`（`x0` 表示设为 VLMAX），导致：

- `vle8.v` 只加载前 n 个元素（vl=n），`vwmul` 只生成 n 个有效乘积；
- v2 寄存器**尾部元素是上一条用例残留的垃圾值**；
- `vsetvli x0` 将 vl 重置为 VLMAX=16，`vwredsum.vs` 对**全部 16 个 e16 元素**归约 → 结果 = 有效乘积 + 垃圾。

复现：e8 vl=4 期望 10，实测 1534；e8 vl=1 期望 5，实测 31748。

### 修复

`vwredsum.vs`/`vredsum.vs` 前的 `vsetvli` 用 `n` 而非 `x0`，让归约严格限定在 vl 个有效元素内：

```c
vsetvli %0, %1, e16, m2 : "=r"(vl) : "r"(n)   // vl = n（关键）
```

修复后 e8 vl=4 → 10、e8 vl=1 → 5，13/13 全部通过。

> 说明：vdot 专用单元天然只归约 vl 个元素（VDotCore 内部按 vl 门控），这是专用指令的语义优势之一，基线必须显式管理 vl。
