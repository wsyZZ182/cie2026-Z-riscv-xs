> 日期：2026-09-17/18

## 一、背景与结论摘要

- 官方赛题对 vdot.vv 只约束语义（SEW=8、VLEN=128），**未规定固定编码**；编码由参赛者自定义，只要不与现有 RVV 标准指令冲突。
- 本作品采用编码 `0x12103157`（funct6=000100、funct3=011、opcode=1010111/OP-V）。
- RTL（香山 yunsuan VDotFu）按 (funct6, funct3) 精确匹配译码，`000100+011` 为空闲保留位，**RTL 侧无冲突**。
- NEMU 的 vopivi 译码表对 funct3 采用 `???` 通配匹配，`funct6=000100` 会被 vminu 条目抢先吞掉，导致协同仿真 mismatch。**解法：只改模拟器侧，把 vdot 精确 pattern 插入 vminu 之前优先匹配，RTL 零改动**，行为一致性由 difftest 逐指令保证。
- 修改 NEMU 两个文件（`decode.h`、`vcompute.h`），重新编译，**协同仿真 13/13 用例全部通过，全程 difftest 无 mismatch，GOOD TRAP 退出**。

## 二、3.1.1 NEMU 指令扩展

### 2.1 编码冲突定位

NEMU 译码路径：`decode.c` 匹配 opcode `1010111` → `OP_V` 按 funct3 分派 8 张表（vopivv=000 / vopfvv=001 / vopmvv=010 / **vopivi=011** / …）。

vdot 的 funct3=011 → 进入 **vopivi 表**。`def_INSTR_TAB` 宏中 funct3 位是 `???` 通配，vopivi 表第 4 条 `"000100 ? ????? ????? ??? ????? ????? ??"`（vminu）会把 `0x12103157` 当作 vminu.vi 译码——**NEMU 宽松匹配必然吞掉 vdot**。

对比 RTL：yunsuan `VAluDecode.scala` 按 (funct6, funct3) 精确匹配，`000100+011` 在 vminu 家族之外、确为空闲保留位，**RTL 不冲突**。

### 2.2 修改文件与内容

**文件 1：`src/isa/riscv64/instr/rvv/decode.h`**（vopivi 表内，vminu 行之前插入一行）

```c
def_INSTR_TAB("000100 ? ????? ????? 011 ????? ????? ??", vdot); // vdot.vv custom dot product, funct3=011 exact match before vminu wildcard
```

精确 pattern 的 funct3=011 与 vdot 编码一致，先于 vminu 的通配条目命中，实现"顺序优先、精确优先"。

**文件 2：`src/isa/riscv64/instr/rvv/vcompute.h`**（`def_EHelper(vdot)` 空壳替换为完整实现）

```c
def_EHelper(vdot) {
  vector_vvv_check(s, false);          // RVV 向量指令合法性与对齐检查
  check_vstart_exception(s);           // vstart != 0 视为非法指令（与 RTL VecExceptionGen 一致）
  if(check_vstart_ignore(s)) {         // vstart 忽略模式（vtype.vill 等）
    vp_set_dirty();
    return;
  }
  // vd 旧值（低 32 位，符号扩展）作为累加初值，与 RTL vdOld 符号扩展进入 CSA 树一致
  get_vreg(id_dest->reg, 0, s1, 2, vtype->vlmul, 1, 0);
  __int128 acc = (__int128)(int64_t)*s1;
  for(word_t idx = vstart->val; idx < vl->val; idx ++) {
    rtlreg_t mask = get_mask(0, idx);          // v0 掩码位
    if(s->vm == 0 && mask == 0) continue;      // 掩码门控，与 RTL 逐元素门控一致
    get_vreg(id_src->reg,  idx, s0, vtype->vsew, vtype->vlmul, 1, 0);  // vs1 元素，符号扩展
    get_vreg(id_src2->reg, idx, s2, vtype->vsew, vtype->vlmul, 1, 0);  // vs2 元素，符号扩展
    acc += (__int128)(int64_t)*s0 * (__int128)(int64_t)*s2;
  }
  // 写回：低 32 位 = acc，高 96 位 = 0（与 RTL Cat(0.U(96.W), full(31,0)) 一致）
  vreg_i(id_dest->reg, 0) = (uint32_t)acc;
  vreg_i(id_dest->reg, 1) = 0;
  vreg_i(id_dest->reg, 2) = 0;
  vreg_i(id_dest->reg, 3) = 0;
  vp_set_dirty();
  vstart->val = 0;
}
```

### 2.3 实现语义（与 RTL VDotCore 逐点对齐）

```
vd[31:0] = sign_ext(vd_old[31:0]) + Σ_{i=0}^{vl-1} ( sign_ext(vs1[i]) * sign_ext(vs2[i]) )
vd[127:32] = 0
```

| 行为点 | NEMU 实现 | RTL 实现 |
|---|---|---|
| 累加初值 | vd 低 32 位符号扩展 | vdOld 符号扩展直入 CSA 树 |
| 元素符号扩展 | get_vreg(..., signed=1) | 按 SEW 有符号乘法 |
| 掩码门控 | vm==0 且 mask==0 跳过 | 逐元素 mask 门控 |
| 写回 | 低 32 位 + 高 96 位清零 | Cat(0.U(96.W), full(31,0)) |
| vxsat CSR | **不写**（RTL MinimalConfig 下 CSR 写回被注释，保持 difftest 一致） | 不写（vxsat 仅内部进位，CSR 链路未接） |
| vstart≠0 | 非法指令 | 执行单元前即判非法（VecExceptionGen） |

> 说明：vxsat 在 RTL 中已算出（`full(31) ^ full(32)`）但 MinimalConfig 下未接线到 vcsr CSR；NEMU 侧同样不写 vcsr，两侧行为一致，difftest 不因 CSR 差异报错。测试程序打印 `vxsat_csr=1 表示链路未接` 印证此设计。

### 3.4 E16 八对：两次请求接入

`vdot.vv` 在 VLEN=128 下 e16 有 **8 个元素**，而 K07 的 e16 契约是「每笔只算输入低 64 位的 4 对」（共享 16 个 BW8 乘法器，一笔 16 对 e8 或 4 对 e16）。因此整核接入对 e16 发**两笔**：

| 笔次 | vs1 / vs2 | mask 重映 | vdOld | 架构写回 |
|---|---|---|---|---|
| 第 1 笔 | 元素 0..3（低 64 位） | `mask[3:0]` | `old_vd[31:0]` | 不写 |
| 第 2 笔 | 元素 4..7（`vs[127:64]` 下移） | `mask[7:4]` | 第 1 笔结果 | 唯一一次 |

`vdOld` 的加法在 K07 的 fused accumulator（CPA 内）完成，所以第 2 笔输出 = `sum(0..7) + old_vd`，与 e8 单笔的 `sum(0..15) + old_vd` 同构；中间值截断到 32 位不影响最终结果（模 2³² 同余）。

**改动范围**：只改 `VDotFu.scala` 一个文件（164 → 241 行，含注释）。`VIAlu`、`VipuCfg`、`K07.sv` 均未改。

**四个时间点**（与 `VipuCfg.latency = 2` 精确对齐，因此不需要把 `VIAlu` 的 `opcodeS2` 拉成三级）：

| 拍 | K07 收到的请求 | K07 输出 | VIAlu `opcodeS2` |
|---|---|---|---|
| `t0`（fire 沿） | 第 1 笔：元素 0..3，`vdOld = old_vd` | 上一条结果 | 上一条 |
| `t1` | 第 2 笔：元素 4..7 下移，`vdOld =` **K07 当前输出** | 第 1 笔结果 | 上一条 |
| `t2` | — | **第 2 笔结果** | **本条 e16 → 写回** |

第 2 笔在 `t1` 组合发出，`vdOld` 直接取 K07 输出寄存器 Q，不构成组合环（Q 到同一组触发器的 D）；`t2` 时 `io.out.vd` 的组合值正好被 `opcodeS2` 采到。e8 走另一条路径：`t1` 沿锁存到 S2 级，由 `vsewS2` 区分。

**背靠背实测**：单独编 `k07-b2b-test`，objdump 确认两条 vdot 的 PC 差 4 字节（真相邻）：

| 用例 | 场景 | 期望 | 实测 |
|---|---|---|---|
| A | 两条 e16 紧邻 | 36 / 36 | 36 / 36 ✅ |
| B | 两条 e16 中间插 `nop` | 36 / 36 | 36 / 36 ✅ |
| C | 两条 e8 紧邻 | 136 / 136 | 136 / 136 ✅ |

RTL 中有 `pass2Conflict` 断言兜底（e16 第 2 笔与新请求争同一端口时触发），实测从未触发——香山 vipu 的实际发射节奏会插入间隔，该断言是防御性检查。若将来采用更激进的发射策略，会先触发断言而不是静默算错。

**复位边界**：`K07.sv` 内部是同步复位（全文唯一的 `always @(posedge clock)` 里 `if (reset)`，且只清 `valid`），但香山整体是异步复位域（`utility/ResetGen` 输出 `AsyncReset`，生成 RTL 中 1619 个模块里 **829 个**使用 `posedge reset`）。因此 BlackBox 的 reset 端口声明为 `Input(AsyncReset())` 并接 `reset.asAsyncReset`。组合语义：K07 在异步断言后要等下一个时钟沿才清 `valid`（复位响应晚一拍），复位期间没有有效事务，功能无害。
