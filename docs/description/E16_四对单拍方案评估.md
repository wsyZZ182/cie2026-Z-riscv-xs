# E16四对、与E8同拍数的方案评估

2026-10-29：用户提出E16只计算四对16×16，以便和E8保持相同时间。本次仅核对BWFast历史源码并分析，未授权/执行RTL修改或测试。

结论：16个BW8足够在一个计算批次并行生成四对16×16所需的16个子乘积；可设计固定拍数E8/E16通路，但现有K07四拍状态机不会因减少有效元素自动变成单拍。需要移除该模式的第二批执行，并将第一批四组结果按0/8/8/16权重组合、与旧值融合压缩和最终CPA放入同一组合阶段。拍数相同可作为设计目标，实际是否满足同一时钟周期必须测量。

源码依据：BWFast_BATCH_RESULTS.zip内src/main/scala/vdot/BWFast.scala:226–247中，E16四组按LL/HL/LH/HH分类，每组并行处理四个元素；229行second选择低/高四个元素。271–276行在寄存器后的合并通路执行位移归并；280–285行明确执行第二批、merge0、merge1。因此仅屏蔽mask高四位或vl=4不会改变当前L=4。

语义必须先决定：128位向量有八个16位元素。若vl=4，则只算低四项符合有效元素范围；若vl>4，不能静默丢弃高四项。可保留原E16八项路径，另加vl≤4固定延迟快速路径，但双延迟会增加调度复杂度；为快速结题更容易考虑同一固定延迟下按模式选择四项快速路径/既有完整E16实现，前提是既有路径满足同一接口与时序，且不重复增加不必要资源。若将指令定义改为固定四项，则属于ISA范围变更，需明确高半向量处理、软件分块累加及NEMU/文档/测试同步，不能把它算作原八项吞吐。

签名/位宽：AL/BL无符号，AH/BH按原符号控制；先融合各带权carry-save行，避免先算四个完整16×16乘积再串加。最终32位模结果与vxsat所需宽和信息分开设计。必须验证四符号、mask、旧值、位权、溢出与flush/背压，报告集成后L/II和STA。
