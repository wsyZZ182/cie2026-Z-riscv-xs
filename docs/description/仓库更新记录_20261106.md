## 1. 源码同步：仓库 vendored 副本对齐生产树

### 问题

`code/stage2/vdot-rtl/` 是整核接入的 vendored 快照，11 个 Scala 文件中有 **2 个与生产树不一致**：

| 文件 | 仓库原值 | 生产树 | 差异性质 |
|---|---|---|---|
| `yunsuan/.../VectorALU/VDotFu.scala` | `488060c0…`（**V-B 竞赛副本**，150 行） | `018da2fd…`（**V-A 工作副本**，164 行） | **真实逻辑差异** |
| `yunsuan/.../vdot/BWFast.scala` | `7854c372…`（301 行） | `ccd16edf…`（303 行） | 仅 `EmitBWFast` 的 firtool 选项 |

**VDotFu 的差异是关键**：V-B 缺 `k07ResultS2` 这一 S2 对齐寄存器，K07 结果直接组合输出；back-to-back 指令会取到错误的 `old_vd`。V-A 才是生产树实际在跑的版本。

### 处置

用生产树覆盖这两个文件。同步后 11/11 全部 SAME。

### 影响

- 之前翻仓库想知道"整核怎么接的"，看到的是**没有 S2 对齐的旧接线**
- 现在仓库快照与生产树一致，`VDotFu.scala` 的 `new BWFastTop` 从第 117 行变为第 **43** 行（行号变化是正常的，因为 V-A 多了 S2 相关代码）

### 为什么可以覆盖而不丢信息

V-B 原文仍在 git 历史里（`git log -- code/stage2/vdot-rtl/.../VDotFu.scala` 可查）。需要历史对照时按 SHA256 `488060c0…` 检索即可。
