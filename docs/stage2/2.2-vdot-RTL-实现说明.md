# 2.2 vdot.vv RTL 实现说明

## 1. 指令定义

自定义向量点积指令 `vdot.vv`：`vd = sum(vs1[i] * vs2[i])`（i < vl），结果写入 vd 低 32 位。

- **编码**：`0x12103157`（二进制 `000100_00001_00011_00000_00000_1010111`）
  - funct6 = `000100`（与 `vminu.vx` 的 funct6 相同，但 funct3 取 `011` 以避开冲突）
  - funct3 = `011`（**修正**：原 `100` 与 RVV 标准指令 `vminu.vx` 冲突，会被误译码为 `vminu.vx v2,v1,x0 = min(v1,0)=0`，导致输出恒 0）
  - opcode = `1010111`（OP-V）
- **语义**：`vd[31:0] = Σ (vs1[i] × vs2[i])`，i = 0..vl-1，元素按 SEW（e8/e16/e32）拆分，有符号乘法，和以 32 位有符号截断写回。

## 3. VDotCore 计算内核

### 3.1 多精度乘法

- **e8**：16 个有符号 8×8 Booth 乘法器（`BoothMultiplier(8)`），乘积 16 位。
- **e16**：8 个有符号 16×16 乘法（Chisel 原生 `*` 操作符）。
- **e32**：4 个有符号 32×32 乘法（Chisel 原生 `*` 操作符）。

> **设计修正**：初期 e16/e32 采用 Karatsuba 递归分解（复用 8×8 Booth 基元），但实测发现 Karatsuba 在 32 位负数路径存在位宽截断缺陷（如 -3×2 算出 0xffffff583837fff8 而非 -6）。经波形与仿真日志定位后，改为 Chisel 原生有符号乘法器（`*`），逻辑等价且面积可接受（e32 仅 4 个乘法器）。

### 3.2 归约累加（符号扩展）

```scala
val sumE8  = (0 until numE8).map  { i => Mux(i.U < io.vl, Cat(Fill(112, prodE8(i)(15)),  prodE8(i)),  0.U(128.W)) }.reduce(_ +& _)
val sumE16 = (0 until numE16).map { i => Mux(i.U < io.vl, Cat(Fill(96,  prodE16(i)(31)), prodE16(i)), 0.U(128.W)) }.reduce(_ +& _)
val sumE32 = (0 until numE32).map { i => Mux(i.U < io.vl, Cat(Fill(64,  prodE32(i)(63)), prodE32(i)), 0.U(128.W)) }.reduce(_ +& _)
```

> **设计修正**：初期用零扩展（`Cat(0.U(...), prod.asUInt)`）累加，负数乘积（如 -1 = 0xFFFF）被当作正数 65535 累加，导致 e8 负数用例结果为 1048440（= 65520..65535 的等差和）而非 -136。改为**符号扩展**（`Fill` 复制符号位）后，负数累加正确。

### 3.3 结果与 tail 处理

- 结果按 SEW 放入 vd 低 32/64/128 位槽（`MuxLookup(io.sew, ...)`）。
- VDotFu 的 `slotMask` **固定为低 32 位**（`0x00000000ffffffff`）——vdot 只产生一个 32 位标量，跨 SEW 统一放 vd 低 32 位。
- ta/vl 语义由 VDotFu 外部处理（`tailVd = (oldVd & ~slotMask) | (redVd & slotMask)`）。

## 4. 关键设计决策

1. **编码避让**：vdot 原编码与 RVV 标准指令 `vminu.vx` 冲突，改为 funct3=011 的空闲编码。
2. **累加符号扩展**：负元素乘积必须符号扩展再累加。
3. **乘法器选择**：Karatsuba 32 位负数路径有缺陷，改用 Chisel 原生乘法器（功能优先，面积后续可优化共享）。
4. **slotMask 固定 32 位**：vdot 标量结果统一放 vd 低 32 位，不随 SEW 截断。
