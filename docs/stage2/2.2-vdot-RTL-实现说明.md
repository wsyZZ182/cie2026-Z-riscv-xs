## 1. 指令定义

自定义向量点积指令 `vdot.vv`：`vd = sum(vs1[i] * vs2[i])`（i < vl），结果写入 vd 低 32 位。

- **编码**：`0x12103157`（二进制 `000100_00001_00011_00000_00000_1010111`）
  - funct6 = `000100`（与 `vminu.vx` 的 funct6 相同，但 funct3 取 `011` 以避开冲突）
  - funct3 = `011`（**修正**：原 `100` 与 RVV 标准指令 `vminu.vx` 冲突，会被误译码为 `vminu.vx v2,v1,x0 = min(v1,0)=0`，导致输出恒 0）
  - opcode = `1010111`（OP-V）
- **语义**：`vd[31:0] = Σ (vs1[i] × vs2[i])`，i = 0..vl-1，元素按 SEW（e8/e16/e32）拆分，有符号乘法，和以 32 位有符号截断写回；结果超出 32 位有符号范围置 vxsat。

## 3. VDotCore 计算内核（前身实现，Fused ReduceAcc 版——**已废弃，仅参考**）

> **版本说明**：本版为 Fused ReduceAcc 优化版（2026-09-14）。相比初版（128 位符号扩展链式归约 + 128 位累加），改动集中在归约累加通路（§3.2），乘法器组与指令接入（§1/§2）不变。旧版 7 用例全部保留，回归 13/13 通过（见 `2.3-功能验证报告.md`）。

### 3.1 多精度乘法——**e8 Booth 与 e16 原生乘法已废弃，仅 e32 仍在用**

- **e8**：16 个有符号 8×8 Booth 乘法器（`BoothMultiplier(8)`），乘积 16 位。
- **e16**：8 个有符号 16×16 乘法（Chisel 原生 `*` 操作符）。
- **e32**：4 个有符号 32×32 乘法（Chisel 原生 `*` 操作符）。

> **设计修正**：初期 e16/e32 采用 Karatsuba 递归分解（复用 8×8 Booth 基元），但实测发现 Karatsuba 在 32 位负数路径存在位宽截断缺陷（如 -3×2 算出 0xffffff583837fff8 而非 -6）。经波形与仿真日志定位后，改为 Chisel 原生有符号乘法器（`*`），逻辑等价且面积可接受（e32 仅 4 个乘法器）。（修复版 Karatsuba 的完整对比与 VDotCore 级影响评估见 `2.4-Karatsuba乘法器算法对比.md` §9/§10，结论是不适合 vdot 场景，主线维持此选型。）

### 3.2 归约累加（Fused ReduceAcc：宽度自适应 + vdOld 融合 + 一次 CPA）——**e8/e16 路径已废弃，仅 e32 仍在用**

```scala
// 各档位宽：容纳"完整点积和 + 32bit vdOld"（原统一 128 位 → 自适应 33/36/67 位）
private val W8  = 33   // 16×16bit 乘积完整有符号和 20bit + vdOld 32bit → 33bit
private val W16 = 36   // 8×32bit 乘积完整有符号和 35bit + vdOld 32bit → 36bit
private val W32 = 67   // 4×64bit 乘积完整有符号和 66bit + vdOld 32bit → 67bit

// vdOld[31:0] 符号扩展为归约的一个操作数（Fused Accumulator）
private val old8  = Cat(Fill(W8  - 32, io.vdOld(31)), io.vdOld(31, 0))

// 乘积与 vdOld 一起进 CSA 压缩树（3→2 逐级压缩）
private val (s8, c8) = reduceCSA(ops8, W8)

// 唯一一次进位传播加法（CPA）
private val full8 = s8 +& c8

// vxsat：full(31) ^ full(32) —— bit32 须为 bit31 的符号扩展，否则截断改变符号
private def overflowOf(full: UInt): Bool = full(31) ^ full(32)

// 结果：统一截断到 32 位标量，放 vd 低 32 位（高 96 位 0，tail 由外壳处理）
io.result := Cat(0.U((vlen - 32).W), fullMux(31, 0))
```

**相对初版的改动与动机**：

1. **宽度自适应（128 位 → 33/36/67 位）**：初版将所有乘积符号扩展到 128 位链式归约，高位大量冗余。按"完整点积和（对数上界）+ 32 位 vdOld"确定各档最小位宽：e8 为 16×16 位乘积和（20 位）+32=33 位，e16 为 35+32=36 位，e32 为 66+32=67 位。组合逻辑面积与功耗随位宽近似线性下降。
2. **Fused Accumulator（vdOld 融合进 CSA）**：初版"先归约成 128 位普通二进制和，再 `acc = oldSlot +& dot128`"需要两次进位传播。新版把 `vdOld[31:0]` 符号扩展后作为归约的一个操作数直接进入 CSA 压缩树，全通路只有 `full = s +& c` 一次 CPA。关键路径缩短为"乘法器 → CSA 树 → 单 CPA"，不再有第二条长进位链。
3. **vxsat 语义修正**：初版 `vxsat = acc(128)`（128 位加法溢出位），在"点积 + 32 位 vdOld"的位宽下几乎永不触发，语义错误。新版定义 vxsat = 结果超出 32 位有符号范围（[−2^31, 2^31−1]），判定为 `full(31) ^ full(32)`。**注意**：不可用"高位全 0/全 1"判定——2^31 时 bit31=1 而 bit32.. 全 0，会被误判为合法负数扩展（首版实现漏报，回归用例 13 暴露后修复）。
4. **删除 vl 掩码**：初版 VDotCore 内 `Mux(i.U < vl, prod, 0)` 与外壳 VDotFu stage0 的 operand gating（按 `(i<vl)&&(vm||mask(i))` 清零乘法器输入）功能冗余，删除内核内掩码，由外壳统一清零。
5. **Booth 乘法器修复**：BoothMultiplier 重写为通用 n 位实现（部分积 `ceil(n/2)` 个、负项取反 +1 修正、符号扩展后移位求和），修复初版 8 位特化实现的部分积数量/符号扩展错误。

### 3.3 结果与 tail 处理（外壳逻辑，**仍适用**）

- 结果**统一截断到 32 位标量**：`result = Cat(0.U(96.W), fullMux(31, 0))`，不随 SEW 改变放位（e8/e16/e32 都在 vd 低 32 位）。
- VDotFu 的 `slotMask` **固定为低 32 位**（`0x00000000ffffffff`）——vdot 只产生一个 32 位标量。
- ta/vl 语义由 VDotFu 外部处理（`tailVd = (oldVd & ~slotMask) | (redVd & slotMask)`）；vl=0 时不执行，vd 保持旧值（见 `2.3-功能验证报告.md` 用例 12）。

### 3.4 K07 交付版的内核与双模式组织

K07 的内核与 §3.1/§3.2 完全不同：**共享 16 个 8×8 BW8 部分积生成器 + 计数树压缩**。e8 一次吃完 16 对（单笔、II=1）；e16 用「同一套 16 个 BW8 分两笔、每笔 4 对」覆盖 8 个元素；e32 仍回退 §3.1/§3.2 的 `VDotCore`。算法选型与 48 版综合对比见 `2.1-vdot-vv-设计文档.md` §7，归约结构见其 §8.3。

`VDotFu.scala`（241 行）按 SEW 选择输入组织，**同一个 K07 实例**服务 E8 与 E16：

```scala
k07E8Mode  = vdType === 0      // 16 个字节 lane，单笔
k07E16Mode = vdType === 1      // 低 4 对 + 高 4 对，两笔
k07Fire    = io.in.valid && (k07E8Mode || k07E16Mode)

k07.io.io_in_bits_vs1 := Mux(pass2Fire, Cat(0.U(64.W), vs1HiS1),
  Mux(k07E8Mode, vs1E8, Cat(0.U(64.W), vs1E16Lo)))
```

E16 的两笔分工：

| 笔次 | vs1 / vs2 | mask 重映 | vdOld | 架构写回 |
|---|---|---|---|---|
| 第 1 笔 | 元素 0..3（低 64 位） | `mask[3:0]` | `old_vd[31:0]` | 不写 |
| 第 2 笔 | 元素 4..7（`vs[127:64]` 下移） | `mask[7:4]` | 第 1 笔结果 | 唯一一次 |

四个时间点（与 `VipuCfg.latency = 2` 对齐，`VIAlu`/`VipuCfg` 未改）：

| 拍 | K07 请求 | K07 输出 | `opcodeS2` |
|---|---|---|---|
| `t0`（fire 沿） | 第 1 笔：元素 0..3，`vdOld=old_vd` | 上一条结果 | 上一条 |
| `t1` | 第 2 笔：元素 4..7 下移，`vdOld=` **K07 当前输出** | 第 1 笔结果 | 上一条 |
| `t2` | — | **第 2 笔结果** | **本条 e16 → 写回** |

E8 走另一条路径：`t1` 沿锁存到 S2 级（`k07E8ResultS2`，`VDotFu.scala:211`：`RegEnable(k07.io.io_out_bits_result, k07.io.io_out_valid && !pass2S2)`），由 `vsewS2` 区分。

RTL 中有 `pass2Conflict`（`VDotFu.scala:102`，`pass2Fire && k07Fire`）断言兜底：e16 第 2 笔与新请求争同一端口时触发。背靠背实测（3 项相邻 e16，PC 差 4 字节）3/3 通过，断言未触发。该断言目前只在 MinimalConfig 下验证过，`KunminghuV2Config` 的背靠背复测仍待做（见 `2.1-vdot-vv-设计文档.md` §13.4）。

### 3.5 K07 的分模式时序（ASAP7 RVT TT，reg→reg）

| 模式 | arrival | FO4 | 最慢路径起点 |
|---|---:|---:|---|
| **E8** | **1759.5 ps** | **98.0** | `io_in_bits_mask[7]` |
| **E16** | **1737.0 ps** | **96.7** | `io_in_bits_mask[3]` |

## 4. 关键设计决策（1、2、4、6 条仍适用；3、5 条属 VDotCore，已废弃）

1. **编码避让**：vdot 原编码与 RVV 标准指令 `vminu.vx` 冲突，改为 funct3=011 的空闲编码。
2. **累加符号扩展**：负元素乘积必须符号扩展再累加（初版零扩展致 e8 负数 1048440 ≠ -136，已修）。
3. **乘法器选择**：Karatsuba 32 位负数路径有缺陷，改用 Chisel 原生乘法器（功能优先；`2.4-Karatsuba乘法器算法对比.md` 已验证修复版 Karatsuba 仍不划算，面积优化方向为 8×8 资源共享，见其 §9/§10）。
4. **slotMask 固定 32 位**：vdot 标量结果统一放 vd 低 32 位，不随 SEW 截断。
5. **Fused ReduceAcc**：宽度自适应（33/36/67）+ vdOld 融合进 CSA + 单次 CPA，消除第二条进位链（性能动机），vxsat 定义为 32 位有符号溢出（`full(31)^full(32)`，语义修正）。
6. **operand gating 上移**：vl/vm/mask 元素清零统一在 VDotFu stage0 完成，VDotCore 不再感知 vl（消除冗余硬件）。

### 4.1 K07 交付版的设计决策

1. **E16 不新增乘法器，改用「同一套 16 个 BW8 + 两笔」**：为满足可扩展性（e16 也要能算），若为 e16 单独做 8 个 16×16 乘法器，面积接近翻倍；两笔复用同一组 BW8，整块只增 106.49 µm²（+2.56%，见 §3.6）。代价是 e16 变 2 拍，且 `t1` 拍存在两笔争用同一端口，用 `pass2Conflict` 断言兜底（见 §3.4）。
2. **BlackBox + 显式 RTL 文件**：`K07.sv` 由独立 Chisel 工程生成，不并入香山 firtool 流程，避免每次整核都重跑生成；代价是必须手工维护 Verilator 文件列表（见 §2.3）。
3. **复位域严格对齐**：`reset` 声明为 `AsyncReset`，与香山 `ResetGen` 一致，避免 VDotFu 自身的寄存器被推断成异步复位单元（见 §2.3；握手与复位详证见 `archive/BWFast_20261030/docs-stage3-legacy/3.10-K07-E16两笔握手与复位.md`）。
4. **e32 不加速，回退 VDotCore**：e32 元素少、收益低，K07 不为它增加 32 位通路；`VDotCore.scala` 因此保留在树内，只为 e32 服务。

### 4.2 验证结果（K07 交付版）

13 项整核 DiffTest（MinimalConfig + NEMU 参考模型逐指令比对）：**13/13 通过**，E16 正 36 / 负 −36，`HIT GOOD TRAP at pc = 0x80000552`，`instrCnt = 17209 / cycleCnt = 63027`，零失配（E8 4/4、E16 2/2、e32 3/3、边界与 vl 4/4）。背靠背 3/3（`HIT GOOD TRAP at pc = 0x800002fa`），build8 与 build3 逐位一致。逐用例明细与阶段一（E8 单模式 700 用例）记录见 `2.1-vdot-vv-设计文档.md` §13.4。
