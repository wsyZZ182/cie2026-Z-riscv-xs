## 1. 定位

`K07E8NextTop` 是 `vdot.vv` 的**窄 E8 专用实现**：只做 16 对 8 位有符号点积，符号、mask、SEW 全部固定。

它有两个用途：

1. **作为当时整核接入版 `BWFastTop` 的 E8 子集**（该版已归档），用来隔离"E8 数据通路本身"的时序与面积；
2. **作为 E8 最终加法器优化的载体**：把原 K07 的 E8 CPA 换成 20+12 分裂前缀加法器。


它**不是**最终交付的整核 RTL。整核里跑的是交付版双模式 `K07`（含动态 SEW/mask/tag/flush；E16 由 `VDotFu` 发两笔覆盖 8 对）。`BWFastTop` 是 2026-10-30 的旧实现，已归档至 `archive/BWFast_20261030/`。

## 2. 指令语义（窄 E8 契约）

```
vd[31:0] = (vdOld + Σ_{i=0..15} int8(vs1[i]) × int8(vs2[i])) mod 2^32
```

| 项 | 取值 |
|---|---|
| 元素宽度 | 固定 E8（`sew = 0`） |
| lane 数 | 16，**全部有效** |
| 符号 | `a_signed = b_signed = true`（固定 SS） |
| mask | 固定 `0xFFFF`（全开） |
| tag | 固定 0 |
| 结果 | 模 2^32，**不输出 vxsat** |
| 延迟 / 启动间隔 | L = 1，II = 1（无背压时） |

## 3. 接口

| 端口 | 方向 | 宽度 | 说明 |
|---|---|---|---|
| `clock` | in | 1 | |
| `reset` | in | 1 | 异步复位 |
| `io_in_valid` | in | 1 | 输入有效 |
| `io_in_bits_vs1` | in | 128 | 被乘数，16 × 8b |
| `io_in_bits_vs2` | in | 128 | 乘数，16 × 8b |
| `io_in_bits_vdOld` | in | 32 | 累加初值 |
| `io_out_valid` | out | 1 | 结果有效 |
| `io_out_bits_result` | out | 32 | 点积结果 |

**没有 `ready` / `flush`**。背压与取消由上层 `VDotFu` 的 active-lane mux 和 VIPU 的 valid 管线负责，不在本模块内。

## 4. 微架构总览

```
vs1[127:0]  vs2[127:0]
     │           │
     ├── 4 组 × 4 个 BW8 部分积生成器（共 16 个 8×8 乘法）
     │        │
     │   组内 3:2 / 4:2 压缩  →  每组两行（Q3 配置保留三行）
     │        │
     └── 4 组结果 + vdOld 拼成 9 个 heap
              │
          e8_merge（再压缩到两行）
              │
      SplitPrefix20x12（32 位两行加法）
              │
         输出寄存器 → result[31:0]
```

资源：`groups=4`、`bw8_generators=16`（由 RTL 生成期打印的 `RESOURCE_SUMMARY` 确认）。

## 5. 关键实现：20+12 分裂前缀加法器

末端 CPA 是 E8 路径的主要瓶颈。`SplitPrefix20x12` 的做法：

1. 低 20 位用 Kogge-Stone 式前缀求 `p/g`，得到低 20 位和与 `carry_out`；
2. 高 12 位**同时算两份**：进位输入为 0 的 `high0`、为 1 的 `high1`；
3. 用低位的 `carry_out` 在 `high0/high1` 之间二选一。

```scala
Cat(Mux(lg(19), high1, high0), low)
```

**唯一的跨边界依赖是"低位 carry → 高位 Mux"**，高位内部的前缀计算与低位完全并行。这是相对原 K07 E8 CPA 的净收益来源：

| 版本 | TT arrival | SS arrival |
|---|---:|---:|
| 原 K07 E8 CPA（`K07E8OnlyTop`） | 1358.0726 ps | 2054.8389 ps |
| **20+12 分裂前缀（`K07E8NextTop`）** | **1308.2151 ps** | **1943.0959 ps** |
| 变化 | −49.86 ps（−3.67%） | −111.74 ps（−5.44%） |

## 7. 与交付版双模式 `K07` 的关系

两者共用同一个前端 `SharedBWFrontend`，`BWFast.scala` 哈希完全相同（`ccd16edf…`）。差异在包装层：

| | `K07E8NextTop` | `K07`（交付版） |
|---|---|---|
| SEW | 固定 E8 | 动态 E8/E16 |
| 符号 | 固定 SS | 动态四模式 |
| mask | 固定全开 | 动态 16 位 |
| tag / flush | 无 | 有 |
| E16 | 不支持 | 每笔 4 对，`VDotFu` 发两笔覆盖 8 对 |
| 延迟 | 1 拍 | E8 1 拍 / E16 2 拍 |
| 面积 | 492 µm² | 671.18 µm² |

因为 `K07E8NextTop` 剥离了全部动态控制，它的时序**不能**代表 `K07`。实测 `K07` 动态模式（reg→reg）为 2128.0 ps / 118.5 FO4，约为 `K07E8NextTop`（1354.2 ps）的 1.6 倍——差值主要来自 E16 模式选择与动态 SEW 选择树，最慢路径起点是 `q_e16`。详见 `docs/stage3/3.3-延迟加速比分析.md` §1。

## 8. 已知限制

1. **无 vl 裁剪**：16 lane 恒全开。vl 由上层 `VDotFu` 的 active-lane zeroing mux 实现，不在本模块。
2. **无 mask**：同上，由上游消费。
3. **无 vxsat**：结果只做模 2^32 截断，不输出饱和标志。整核版的 vxsat 由 `VDotCore` 的溢出判据产生（该判据在 2026-11-06 的 P2 中被发现存在 E32 缺陷，已另案修正）。
4. **未做形式验证**：等价性只做过有限随机回归。
5. **时序为 ASAP7 代理**：绝对 ps 不可迁移到真实工艺。
