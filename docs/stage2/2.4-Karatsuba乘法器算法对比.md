## 1. 背景与定位

主线 `vdot.vv` 在 `VDotCore` 中按元素位宽选用乘法器：

| 元素位宽 | 数量 (VLEN=128) | 主线乘法器 | 乘积位宽 |
| ---- | ------------- | ----------------------------------- | ---- |

| e16  | 8             | Chisel 原生 `*`                       | 32   |
| e32  | 4             | Chisel 原生 `*`                       | 64   |

`VDotCore.scala` 中保留了一个**未接入**的 `object Karatsuba` / `KaratsubaMultiplier`，注释说明「32 位负数路径存在缺陷」。本文的目标是：

1. 正确实现 Karatsuba 有符号乘法器（修复当年负数路径缺陷）；
2. 与原生、Radix-4 Booth、传统分块乘法（Schoolbook）在**相同源、相同流程**下比较**面积**与**关键路径延迟**；
3. 给出 Karatsuba 是否适合 `vdot` 场景的结论，并进一步评估其接入 VDotCore 后对面积/延迟/吞吐的实际影响（§9）以及乘法器资源共享的可重构性（§10）。

## 2. 四种乘法器原理

设两个 n 位有符号补码操作数 a、b，结果为 2n 位。

### 2.1 Native（原生 `*`）

直接使用 HDL 的乘法运算符 `p = a * b`，由综合器内部的乘法器生成器决定具体结构。作为「工具默认」基线。

### 2.2 Radix-4 Booth（基 4 布斯）

从 `{sign(b), b, 1'b0}` 每次取相邻 3 位，按 Booth 编码选择部分积 `0 / +a / -a / +2a / -2a`，共 ⌈(n+1)/2⌉ 个部分积（16 位→8 个，32 位→16 个），负项取反并在最低位 +1，逐级算术左移累加后取低 2n 位。优点是部分积数目约为学校法的一半。

### 2.3 Schoolbook（传统分块乘法，4 次小乘法）

将操作数按高低半拆分：`a = a1·2^h + a0`，`b = b1·2^h + b0`（h=n/2），则

```
a·b = z2·2^(2h) + z1·2^h + z0

z0 = a0·b0

z1 = a0·b1 + a1·b0

z2 = a1·b1
```

一次 n 位乘法需要 **4 个 h 位乘法器**（z1 的两个交叉项各一个）。

### 2.4 Karatsuba（3 次小乘法）

利用恒等式复用一次乘法：

```
zm = (a1 + a0)(b1 + b0)

z0 = a0·b0

z2 = a1·b1

z1 = zm − z2 − z0

a·b = z2·2^(2h) + z1·2^h + z0
```

一次 n 位乘法只需 **3 个小乘法器**（z2、z0、zm），用额外的加减换 1 次乘法。递归应用时门数复杂度由学校法的 O (n²) 降为 **O(n^log2 3) ≈ O(n^1.585)**。

## 3. Karatsuba 有符号扩展的三个关键点（当年缺陷根因）

Karatsuba 最初为无符号数提出；直接搬到补码有符号数，若位宽处理不当就会在负数 / 大数路径出错。正确实现必须同时满足以下三点：

1. **和要变宽**：`(a1 + a0)` 中 a1 是 h 位有符号数、a0 是 h 位非负数，其和范围超出 h 位（8 位拆分时为 −128…382，需 **h+2=10 位**；32 位为 18 位）。因此计算 zm 的乘法器必须比叶子基元更宽；32 位递归第二层是更宽的和，塞回原通路即发生**位宽截断**。
2. **交叉项 z1 可能为负**：`z1 = zm − z2 − z0` 必须按**有符号补码**保留符号位，并符号扩展到全位宽后再参与重组；按无符号宽度截断会在 z1<0 时出错。
3. **低位必须零扩展（队友当年 bug 根因）**：低半部分 a0、b0 及其乘积 z0 都是非负的，必须**零扩展**。原 `KaratsubaMultiplier` 在重组时对低位乘积 z0 误用 `.asSInt`（符号扩展），把本应为正的 `255×255 = 65025` 算成了 `−511`；小的正数碰巧正确，故仅在边界 / 大值时暴露。高半 a1、b1 才按有符号处理并带负权。

本设计按上述三点实现（低位零扩展为非负、统一补码、和变宽、交叉项留符号），功能仿真在全部边界与随机用例上通过，证明修正有效。

## 5. 评估方法与口径

为保证 4 种算法公平可比，所有设计使用**完全相同的源集合、综合脚本与命令**。

### 5.1 面积：归一化等效门

完整 `yosys synth -flatten`（默认 abc 用内置 generic 库）后统计各类门，按逻辑复杂度加权为归一化等效门（INV=1）：

| generic 门                                 | 权重  |
| ----------------------------------------- | --- |
| `$_NOT_`                                  | 1   |
| `$_NAND_` `$_NOR_` `$_ANDNOT_` `$_ORNOT_` | 1.5 |
| `$_AND_` `$_OR_`                          | 2   |
| `$_XOR_` `$_XNOR_`                        | 3.5 |
| `$_MUX_`                                  | 3   |

### 5.2 延迟：AIG 关键路径深度

`yosys synth -noabc` 写 BLIF，由 `abc print_stats` 读取 AIG 的 **lev（逻辑级数）**，即关键路径上的逻辑门深度，作为不依赖特定工艺的延迟代理。

### 5.3 口径说明与局限

* 本机 yosys-abc 的标准单元库读取（SCL `read_lib` / `read_genlib`）在该环境下均异常（模板未识别 / 断言崩溃 / 段错误），无法映射到带绝对延迟的标准单元，故采用 yosys 原生、可复现的「等效门 + 逻辑深度」口径。
* 该口径反映**算法结构层面**的面积与关键路径，**不含**具体工艺、布线负载与单元尺寸差异；
* 结论为算法间**相对**比较，非绝对物理数值。取得真实 PDK Liberty + OpenSTA 后可补充绝对数据。

## 7. 分析

1. **16 位（一层递归）：Karatsuba 面积、延迟双输。**
   面积比学校法大 9.1%、关键路径深 34%。原因是只递归一层时，「和变宽」（zm 用到 10 位乘法器）与交叉项加减的**常数项开销**，超过了「少一个乘法器」节省的面积。Karatsuba 的渐近优势在 n 很小时不成立。

2. **32 位（两层递归）：开始用延迟换面积。**
   面积比学校法省 7.5%、比原生省 5.6%，递归省乘法器的收益开始超过常数项；但关键路径深度显著增加（比学校法 +54%、比原生 +109%）。深度来自递归的**串行依赖**：zm 依赖先算和、z1 依赖 zm/z2/z0 三者就绪、最后还要移位相加，这些在学校法中更浅。

3. **本质权衡**：Karatsuba 降低的是**乘法（面积）渐近复杂度 O (n^1.585)**，代价是更深、更串行的关键路径。它优化的是面积而非延迟；若不做流水线，组合 Karatsuba 的延迟随递归层数明显变差。

4. **Schoolbook 并行性显著优于 Karatsuba（本文补充对比）**：Schoolbook 的四个子乘法 `z0 = a0b0`、`z1a = a0b1`、`z1b = a1b0`、`z2 = a1b1` 输入都是**原始操作数的位切片**，相互无依赖、可完全并行，仅末级一次移位相加；Karatsuba 则是 `pre-add → zm → subtract → combine` 的串行链。这解释了 §6 中 Schoolbook 深度只比 Native 多 17%（41 vs 35）和 36%（61 vs 45），而 Karatsuba 多 57% 和 109%。同时 **Schoolbook16 是四种方案中唯一面积比 Native 还小的**（4244.5 vs 4357，−2.6%），其代价仅为深度 +17%（6 级）。

## 8. 对 `vdot` 的适用性结论

* `vdot` 的性能目标是**吞吐 / 延迟**（阶段三 3.3 主要测量吞吐加速比），且乘法器位宽小（e8/e16 为主，e32 仅 4 个）。
* 在 8/16 位这个区间，Karatsuba 既不省面积又显著加深关键路径；32 位虽省约 6% 面积，却使关键路径翻倍，不利于点积的高频 / 高吞吐实现。
* 因此主线在 e8 用 Booth（部分积数目减半）、e16/e32 用原生乘法器是合理选择，**当年弃用 Karatsuba、仅保留为工程化方向的判断与本文证据一致**。
* Karatsuba 更适合的场景：**面积 / 资源严格受限、操作数位宽大、对单条延迟不敏感、或可通过多级流水线把递归深度摊到不同周期**的实现（如超宽整数、面积优先的嵌入式数据通路）。

## 9. VDotCore 级影响评估（将乘法器单点结论合成到整条数据通路）

§6–§8 是**乘法器单点**口径。VDotCore 实际由 28 个乘法器 + 宽度自适应 CSA 归约树（33/36/67 位）+ 单次 CPA 组成，三条精度通路（e8/e16/e32）并行、由 `MuxLookup(sew)` 选通，**主时钟周期受最深通路限制**。以下把 Karatsuba 替换 16/32 位乘法器后的影响合成到 VDotCore 整体。

### 9.1 乘法器组面积合成

| 档位 | 主线乘法器（等效门/个 × 数量） | 小计 | Karatsuba 版（等效门/个 × 数量） | 小计 | 差值 |
|---|---|---|---|---|---|
| e8 | Booth8 ≈2178* × 16 | 34,848 | Booth8（不变） | 34,848 | 0 |
| e16 | Native16 4357 × 8 | 34,856 | Kar16 4632.5 × 8 | 37,060 | **+2204** |
| e32 | Native32 16489.5 × 4 | 65,958 | Kar32 15558 × 4 | 62,232 | **−3726** |
| **合计** | | **135,662** | | **134,140** | **−1522（−1.1%）** |

> *Booth8 无直接实测（本组实验只测了 16/32 位 Booth），按 Booth16（4355、8 组部分积）半组数线性估算 ≈2178，为估算口径。e16 换 Karatsuba 每个贵 6.3%（8 个 → +2204）与 e32 省 5.6%（4 个 → −3726）基本抵消；再叠加 CSA 树/外壳固定开销后，**VDotCore 整体面积净收益趋近于零（<1%）**。

### 9.2 关键路径（决定主频）

| 档位 | 主线深度 | Karatsuba 版深度 | 变化 |
|---|---|---|---|
| e16 通路 | 35 级 | 55 级 | **+57%** |
| e32 通路 | 45 级 | 94 级 | **+109%** |

VDotCore 整体最深通路为 e32（45 级 + CSA + 67 位 CPA ≈ 70 级量级），换 Karatsuba 后 ≈ 94 级 + CSA + CPA ≈ 120 级量级——**关键路径约翻倍**。香山目标频率下每周期逻辑级数预算有限（AIG 约 20~30 级量级），Kar32 单乘法器即 94 级，**现有 2 拍延迟（S1 锁存 + S2 CPA）必然装不下**，只有两条出路：

- **路 A：不切流水** → 目标频率下时序违例，只能降频 → 周期数不变但 wall-clock 吞吐约减半；
- **路 B：切流水**（Kar32 递归深度摊到 3~4 拍）→ vdot 延迟 2→3~4 拍，背靠背间隔拉长，周期级吞吐变差。

路 B 是必然选择（Kar32 深度决定了它无法留在 2 拍内）。

### 9.3 吞吐与加速比（机制性估算，非实测）

吞吐（周期/op）由流水结构决定，乘法器深度只决定时钟能否收敛；Karatsuba 版必须切流水后，基于 3.3 实测基线估算：

| 指标 | 主线实测（3.3） | Karatsuba 版（估算） | 变化 |
|---|---|---|---|
| Latency e8 | ≈7.0 | ≈7.0（Booth8 不变） | 持平 |
| Latency e16/e32 | ≈7.0 | **8 ~ 10** | 变差 |
| Throughput e8/e16 | 1.78 | **2.5 ~ 3.0** | +40%~70% |
| Throughput e32 | 1.78 | 2.5 ~ 3.0 | +40%~70% |
| **加速比 e8/e16**（vs 基线 7.1） | **≈4.0×** | 7.1 ÷ 2.5~3.0 ≈ **2.4 ~ 2.8×** | 下降约 1/3 |
| **加速比 e32**（vs 基线 2.7） | **≈1.5×** | 2.7 ÷ 2.5~3.0 ≈ **0.9 ~ 1.1×** | **加速比消失，可能被基线反超** |

> 估算前提：Kar32（94 级）+ CSA + 67 位 CPA 必须切流水（路 B），周期数 = 流水级数约束下的发射间隔 + 写回等待。此为**机制性估算**，精确数字需把 Kar16/Kar32 实际接入 VDotCore 后做 yosys 级整体综合与 12 kernel 回归（见 §12 后续方向 ④）。

### 9.4 小结

Karatsuba 接入 VDotCore：**面积省 <1%、关键路径翻倍、延迟变差、吞吐 +40%~70%、e32 加速比从 1.5× 归零（可能被基线反超）**。§8「Karatsuba 不适合 vdot 主线」的结论在整条数据通路层面进一步坐实。

## 10. 资源共享与可重构性设计空间（乘法器算法之外的优化方向）

将 vdot 的 28 个乘法器按 SEW 互斥运行（e8 只用 e8 bank、e16 只用 e16 bank、e32 只用 e32 bank）但三套硬件同时存在，是比"换乘法器算法"潜力更大的优化方向。本节从可重构性角度比较 Karatsuba 与 Schoolbook。

### 10.1 为什么 Karatsuba 的中间乘法器抽不出来当 8/16 位用

Kar32 内部嵌 5 个叶子（Base#8/9/10/17/18），但：

1. **输入是"和"不是位切片**：`zm = (a1+a0)(b1+b0)` 的输入是**加法结果**（18 位），不是操作数的位切片。抽出来当 8×8 用毫无意义——没有可接的外部数据；Karatsuba 的 10/18 位乘法器是为公式量身定做的，**无法外置修正**。
2. **并行度不够**：一颗 Kar32 里只有 1 个 Base#8、1 个 MulKar16。e8 要 16 个并行 8×8，得放 16 颗 Kar32（16×15558 ≈ 24.9 万门，比 16 个 Booth8 ≈ 3.5 万门贵 7 倍）；e16 要 8 个并行 16×16，4 颗 Kar32 只能切出 4 个。
3. **位宽不规整**：8/9/10/17/18 混合，不是统一的 8×8 或 16×16。

### 10.2 Schoolbook 更接近可重构，但现有实现同样不规整

Schoolbook 的四个子乘法是**原始位切片的乘积**（`a1b1 / a1b0 / a0b1 / a0b0`），这正是"大乘法拆小乘法"（Comba）的标准结构，天然适合共享阵列。但：

- 现有 `MulSchool16 = 1×Base8 + 3×Base9`、`MulSchool32 = 1×Kar16 + 3×Base17`：9/17 位来自高位**符号扩展 +1** 与低位**零扩展 +1**——**可以外置**（用 8×8 基元 + MUX 选符号 + 末级修正），而 Karatsuba 的和变宽**无法外置**。这是两者可重构性差异的本质：**Schoolbook 的不规整来自符号扩展（可修正），Karatsuba 的不规整来自和乘法（不可修正）**。
- School32 高半复用 `MulKar16` 是"与 Kar32 口径公平"的对比选择，若用于共享阵列应换回 Native16 或 4×Base8。

### 10.3 共享 8×8 基元池方案（设计空间）

以 Base8 ≈ 866 等效门（由 School16 = 1×Base8 + 3×Base9 = 4244.5 反推，估算口径）为单元：

| 方案 | 结构 | 乘法器组面积 | e16 关键路径 | e16 吞吐 | 说明 |
|---|---|---|---|---|---|
| A：完全并行（现状） | 16 Booth8 + 8 Nat16 + 4 Nat32 | ≈135,700 | 35 级 | 1.78 | 已交付主线 |
| B：共享 32 基元（e8+e16 全并行） | 32 × 8×8 + 符号修正 + Wallace 拼接 | ≈2.8 万 + 路由 ≈ **3~4 万（省 ~70%）** | 8×8 深度 + 4合1 ≈ 35~40 级 | 1.78 | 四维不亏，但 e8 只用 16 个（利用率 50%） |
| C：共享 16 基元 × 2 子周期 | 16 × 8×8 + 调度 | ≈1.4 万 + 逻辑 ≈ **~2 万（省 ~85%）** | 同上 | **~2.5+（变差）** | 需要多指令重叠调度，香山顺序发射难兑现 |
| 含 e32 的全共享 | 64 × 8×8 | ≈5.5 万 + 修正/路由 ≈ 7~8 万（省 ~45~50%） | 8×8 + 16合1 ≈ 45 级（≈ Native32） | 视调度 | 需要 MUX 路由 + 符号修正 + 拼接网络 |

**只做 e8/e16（放弃 e32）的变体**：若砍掉 e32 bank，独立阵列省 49%；方案 B 省 ~70% 且吞吐/深度不亏——但均以**收缩指令语义（弃 e32）**为代价，需同时回改 2.1 文档/NEMU/用例/3.3 报告，作品完整性上为负分项，**主线不采纳**，仅作设计空间记录。

### 10.4 结论

1. 可重构乘法器的**数学基础是 Schoolbook（Comba 位切片），不是 Karatsuba**（和乘法无法外置修正）；
2. 真正值得做的共享方案是"8×8 基元池 + 符号修正 + Wallace 拼接"，面积收益 45%~70%，但需要 MUX 路由/符号修正/（或）调度逻辑，且动指令语义；
3. vdot 主线维持 e8 Booth / e16 / e32 原生、28 乘法器全实例化是**当前时间约束下的正确决策**；共享阵列作为赛后的研究/设计空间方向保留。
