## 1. 背景与定位

主线 `vdot.vv` 在 `VDotCore` 中按元素位宽选用乘法器：



| 元素位宽 | 数量 (VLEN=128) | 主线乘法器                               | 乘积位宽 |
| ---- | ------------- | ----------------------------------- | ---- |
| e8   | 16            | Radix-4 Booth（自研 `BoothMultiplier`） | 16   |
| e16  | 8             | Chisel 原生 `*`                       | 32   |
| e32  | 4             | Chisel 原生 `*`                       | 64   |

`VDotCore.scala` 中保留了一个**未接入**的 `object Karatsuba` / `KaratsubaMultiplier`，

注释说明「32 位负数路径存在缺陷」。本文的目标是：



1. 正确实现 Karatsuba 有符号乘法器（修复当年负数路径缺陷）；

2. 与原生、Radix-4 Booth、学校法（Schoolbook）分治乘法器在**相同源、相同流程**下

   比较**面积**与**关键路径延迟**；

3. 给出 Karatsuba 是否适合 `vdot` 场景的结论。

## 2. 四种乘法器原理

设两个 n 位有符号补码操作数 a、b，结果为 2n 位。

### 2.1 Native（原生 `*`）

直接使用 HDL 的乘法运算符 `p = a * b`，由综合器内部的乘法器生成器决定具体结构。

作为「工具默认」基线。

### 2.2 Radix-4 Booth（基 4 布斯）

从 `{sign(b), b, 1'b0}` 每次取相邻 3 位，按 Booth 编码选择部分积 `0 / +a / -a / +2a / -2a`，

共 ⌈(n+1)/2⌉ 个部分积（16 位→8 个，32 位→16 个），负项取反并在最低位 +1，

逐级算术左移累加后取低 2n 位。优点是部分积数目约为学校法的一半。

### 2.3 Schoolbook（学校法 / 分治，4 次小乘法）

将操作数按高低半拆分：`a = a1·2^h + a0`，`b = b1·2^h + b0`（h=n/2），则



```
a·b = z2·2^(2h) + z1·2^h + z0

z0 = a0·b0

z1 = a0·b1 + a1·b0

z2 = a1·b1
```

一次 n 位乘法需要 **4 个 h 位乘法器**（z1 的两个交叉项各一个）。

### 2.4 Karatsuba（3 次小乘法）

利用恒等式复用一次乘法：



```
zm = (a1 + a0)(b1 + b0)

z0 = a0·b0

z2 = a1·b1

z1 = zm − z2 − z0

a·b = z2·2^(2h) + z1·2^h + z0
```

一次 n 位乘法只需 **3 个小乘法器**（z2、z0、zm），用额外的加减换 1 次乘法。

递归应用时门数复杂度由学校法的 O (n²) 降为 **O(n^log2 3) ≈ O(n^1.585)**。

## 3. Karatsuba 有符号扩展的三个关键点（当年缺陷根因）

Karatsuba 最初为无符号数提出；直接搬到补码有符号数，若位宽处理不当就会在负数 / 大数路径出错。

正确实现必须同时满足以下三点：



1. **和要变宽**：`(a1 + a0)` 中 a1 是 h 位有符号数、a0 是 h 位非负数，

   其和范围超出 h 位（8 位拆分时为 −128…382，需 **h+2=10 位**；32 位为 18 位）。

   因此计算 zm 的乘法器必须比叶子基元更宽；32 位递归第二层是更宽的和，

   塞回原通路即发生**位宽截断**。

2. **交叉项 z1 可能为负**：`z1 = zm − z2 − z0` 必须按**有符号补码**保留符号位，

   并符号扩展到全位宽后再参与重组；按无符号宽度截断会在 z1<0 时出错。

3. **低位必须零扩展（队友当年 bug 根因）**：低半部分 a0、b0 及其乘积 z0 都是非负的，

   必须**零扩展**。原 `KaratsubaMultiplier` 在重组时对低位乘积 z0 误用 `.asSInt`（符号扩展），

   把本应为正的 `255×255 = 65025` 算成了 `−511`；小的正数碰巧正确，故仅在边界 / 大值时暴露。

   高半 a1、b1 才按有符号处理并带负权。

本设计按上述三点实现（低位零扩展为非负、统一补码、和变宽、交叉项留符号），

功能仿真在全部边界与随机用例上通过，证明修正有效。

## 5. 评估方法与口径

为保证 4 种算法公平可比，所有设计使用**完全相同的源集合、综合脚本与命令**。

### 5.1 面积：归一化等效门

完整 `yosys synth -flatten`（默认 abc 用内置 generic 库）后统计各类门，

按逻辑复杂度加权为归一化等效门（INV=1）：



| generic 门                                 | 权重  |
| ----------------------------------------- | --- |
| `$_NOT_`                                  | 1   |
| `$_NAND_` `$_NOR_` `$_ANDNOT_` `$_ORNOT_` | 1.5 |
| `$_AND_` `$_OR_`                          | 2   |
| `$_XOR_` `$_XNOR_`                        | 3.5 |
| `$_MUX_`                                  | 3   |

### 5.2 延迟：AIG 关键路径深度

`yosys synth -noabc` 写 BLIF，由 `abc print_stats` 读取 AIG 的 **lev（逻辑级数）**，

即关键路径上的逻辑门深度，作为不依赖特定工艺的延迟代理。

### 5.3 口径说明与局限



* 本机 yosys-abc 的标准单元库读取（SCL `read_lib` / `read_genlib`）在该环境下均异常

  （模板未识别 / 断言崩溃 / 段错误），无法映射到带绝对延迟的标准单元，

  故采用 yosys 原生、可复现的「等效门 + 逻辑深度」口径。

* 该口径反映**算法结构层面**的面积与关键路径，**不含**具体工艺、布线负载与单元尺寸差异；

* 结论为算法间**相对**比较，非绝对物理数值。取得真实 PDK Liberty + OpenSTA 后可补充绝对数据。

## 7. 分析



1. **16 位（一层递归）：Karatsuba 面积、延迟双输。**

   面积比学校法大 9.1%、关键路径深 34%。原因是只递归一层时，

   「和变宽」（zm 用到 10 位乘法器）与交叉项加减的**常数项开销**，

   超过了「少一个乘法器」节省的面积。Karatsuba 的渐近优势在 n 很小时不成立。

2. **32 位（两层递归）：开始用延迟换面积。**

   面积比学校法省 7.5%、比原生省 5.6%，递归省乘法器的收益开始超过常数项；

   但关键路径深度显著增加（比学校法 +54%、比原生 +109%）。

   深度来自递归的**串行依赖**：zm 依赖先算和、z1 依赖 zm/z2/z0 三者就绪、

   最后还要移位相加，这些在学校法中更浅。

3. **本质权衡**：Karatsuba 降低的是**乘法（面积）渐近复杂度 O (n^1.585)**，

   代价是更深、更串行的关键路径。它优化的是面积而非延迟；

   若不做流水线，组合 Karatsuba 的延迟随递归层数明显变差。

## 8. 对 `vdot` 的适用性结论



* `vdot` 的性能目标是**吞吐 / 延迟**（阶段三 3.3 主要测量吞吐加速比），

  且乘法器位宽小（e8/e16 为主，e32 仅 4 个）。

* 在 8/16 位这个区间，Karatsuba 既不省面积又显著加深关键路径；

  32 位虽省约 6% 面积，却使关键路径翻倍，不利于点积的高频 / 高吞吐实现。

* 因此主线在 e8 用 Booth（部分积数目减半）、e16/e32 用原生乘法器是合理选择，

  **当年弃用 Karatsuba、仅保留为工程化方向的判断与本文证据一致**。

* Karatsuba 更适合的场景：**面积 / 资源严格受限、操作数位宽大、对单条延迟不敏感、**

  **或可通过多级流水线把递归深度摊到不同周期**的实现（如超宽整数、面积优先的嵌入式数据通路）。
