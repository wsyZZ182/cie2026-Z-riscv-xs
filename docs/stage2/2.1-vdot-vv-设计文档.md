## 1. 概述

vdot.vv 是一条**自定义向量归约指令**：单条指令完成"逐元素乘法 → 全向量归约求和 → 累加到目标寄存器"三个操作，将 RVV 基线中 `vmul.vv` + `vredsum.vs` 两条指令（含一次额外向量寄存器写回）压缩为一条指令。

| 对比项 | 基线（vmul.vv + vredsum.vs） | vdot.vv |
|---|---|---|
| 指令数 | 2 | 1 |
| 中间写回 | 一次 vd 写回 | 无 |
| 语义 | 逐元素乘，再单独归约 | 乘+归约+累加融合 |

本指令支持 e8 / e16 / e32 三种精度，可配置有效元素数（vl），并携带定点溢出标志（vxsat），面向嵌入式 AI 推理等"内积密集"场景。

## 2. 指令编码

vdot.vv 采用 RVV 1.0 的 **OP-V** 指令格式，编码位于 `OPMVV` 归约子空间。**关键约束**：初版选用 `funct3 = 100`，但实测该编码与 RVV 标准指令 **`vminu.vx`**（`funct6=000100, funct3=100`）冲突——`vdot.vv v2, v1, v0` 会被香山译码为 `vminu.vx v2, v1, x0 = min(v1, 0) = 0`，导致输出恒 0 且 DiffTest 误判"通过"。经核对 rocket-chip 译码表，`funct6=000100 / funct3=011` 位置空闲，故最终编码采用 **`funct3 = 011`**。

### 2.1 编码格式（最终版）

```
31                26 25 24              20 19              15 14        12 11             7 6             0
┌──────────────────┬──┬──────────────────┬──────────────────┬───────────┬──────────────────┬──────────────┐
│      funct6      │vm│       vs2        │       vs1        │  funct3   │       vd         │    opcode    │
│      000100      │  │                  │                  │   011     │                  │   1010111    │
└──────────────────┴──┴──────────────────┴──────────────────┴───────────┴──────────────────┴──────────────┘
  vdot.vv vd, vs2, vs1, vm     → 编码 0x12103157
```

字段说明：

- `funct6 = 000100`：本指令专用编码，位于 `OPMVV` 归约扩展区。
- `vm`：按 RVV 规范，控制掩码寄存器 `v0` 是否参与计算。
- `vs2` / `vs1`：两个参与逐元素乘法的源向量寄存器。
- `vd`：目标寄存器，结果写回到 `vd[31:0]`，其余槽按尾策略处理。
- `funct3 = 011`：**修正值**（初版 `100` 与 `vminu.vx` 冲突，见上）。
- `opcode = 1010111`：RVV `OP-V` 指令编码。

### 2.2 编码分配（修正后）

```
OPMVV (funct3 = 011 子空间)
├── 000100 / 011 : vdot.vv   ← 采用编码（rocket-chip 译码表确认空闲）
└── 其余 : 保留 / 扩展

（注：funct3 = 100 子空间含 vminu.vx 等标准指令，初版编码 0x12104157 已废弃）
```

编码策略：避开 RVV 标准指令占用的 `funct6/funct3` 组合，选 rocket-chip 译码表中确认为空闲的位置，满足"新增指令、最小侵入、兼容性优先"。

## 3. 指令语义

### 3.1 伪代码

```
vdot.vv vd, vs2, vs1, vm:
  for i in 0 .. vl-1:
    if vm == 0 and v0[i] == 0: skip        # 掩码元素跳过
    acc += sign_ext(vs1[i], SEW) * sign_ext(vs2[i], SEW)   # 乘积精确（2×SEW 位）
  vd[31:0] = acc + vd_old[31:0]            # 累加旧值，截断到 32 位标量
  if 累加溢出: vxsat = 1                    # 当前策略：置位但不饱和
  vd[127:32] = oldVd[127:32]               # 高槽保留旧值（ta=0）或全 1（ta=1），由外壳处理
```

### 3.2 三种精度行为

| SEW（vsew 编码） | 元素数（VLEN=128） | 乘积宽度 | 累加目标槽 | vd 其余槽 |
|---|---|---|---|---|
| e8（`00`） | 16 | 16 位（精确） | vd[31:0] | 保留旧值（ta=0） |
| e16（`01`） | 8 | 32 位（精确） | vd[31:0] | 保留旧值（ta=0） |
| e32（`10`） | 4 | 64 位（精确） | vd[31:0] | 保留旧值（ta=0） |

> **说明（v1.1 修订）**：vdot 产生一个 **32 位标量**（点积和截断到 32 位有符号），统一写回 `vd[31:0]`（`slotMask` 固定低 32 位），高 96 位按尾策略（ta）由外壳处理。初版设计中 e16 写 `vd[63:0]`、e32 写 `vd[127:0]` 的方案已废弃——点积和按 32 位标量语义截断，与 2.3 测试用例（e16=36、e32=-128 均在 32 位内）一致。

### 3.3 边界规则

1. **vl 掩码**：仅 `i < vl` 的元素参与归约，其余元素贡献 0（由内核掩码实现，见 §7.4）。
2. **尾元素**：`i ≥ vl` 的 vd 槽按 RVV 尾策略（vta）由外壳处理；本内核输出 0。
3. **溢出**：乘积不溢出（宽度 2×SEW 精确），仅**累加阶段**可能溢出。当前策略为**截断 + vxsat 置位**（VDotCore 中 `acc(128)` 为溢出位）；如需饱和语义可在累加器扩展（§9 有说明）。
4. **vstart / 掩码**：按 RVV 规范由外壳（VecPipedFuncUnit + Mgu）处理，内核接口不含 vstart（对齐 Reduction.scala 的归约范式）。

### 3.4 与阶段三 NEMU 的契约

本文档 §3.1–§3.3 语义是阶段三 NEMU 参考实现（`vdot.vv` 模拟逻辑）的**唯一依据**。NEMU 端必须实现：三精度符号乘法、vl 掩码、与 vd[31:0] 累加、截断 + vxsat。

## 4. 设计目标与约束

### 4.1 对标基线

参考实现 nanhu-vdot（arXiv 2409.00661）采用**固定 8-bit 乘法器阵列**（8 路 8×8 乘法器 + 7 个加法器，输出 64 位），仅支持单一精度。本设计支持 **e8/e16/e32 三精度**。

### 4.2 设计约束

| 约束 | 取值 | 依据 |
|---|---|---|
| VLEN | 128 位 | 香山向量寄存器位宽 |
| SEW | e8 / e16 / e32 | 比赛 2.3 测试要求（正/负/边界） |
| 结果精度 | 精确（乘积 2×SEW 位），累加截断到 32 位标量 | 边界值测试需精确比对 |
| 延迟 | 2 拍（CertainLatency(2)） | 乘+归约+累加两拍完成 |
| 吞吐 | back-to-back，1 条/周期 | piped=true + 流水化 |

### 4.3 优化边界（算法选型）

> **定理（下界）**：精确计算任意两个长度 K 的运行时向量的点积，至少需要 K 次乘法。优化空间只在面积、延迟、吞吐三个维度。

经调研，Fast Inner Product（FIP，Winograd 1968）及 Free-Pipelined FIP（arXiv 2311.12224）等"减乘法"算法依赖多输出间的中间结果复用（α/β 项），仅适用于矩阵乘法/脉动阵列场景；位层 MAC、分布式算术、查表法分别依赖权重稀疏性、固定系数等前提，均与 vdot.vv 的单指令、运行时操作数、精确计算约束不兼容。单条点积的乘法次数下界为 K，本设计将优化集中于微架构层：**Radix-4 Booth 编码乘法器**减半部分积（e8，**v1.4 起已被 K07 计数树取代**，见 §7.1b）；**Chisel 原生有符号乘法器**保证 e32 正确性与时序收敛（e16 亦已于 v1.4 改 K07 两笔，见 §7.3b）；**流水化**实现 back-to-back 发射。e16/e32 曾尝试 **Karatsuba 位分解**复用 8×8 基元以压缩面积，但验证发现其 32 位负数路径存在位宽截断缺陷，最终**弃用**、改用原生乘法器（详见 §7.2 修正记录）；后经 2.4 实验验证，**修复版 Karatsuba 在 vdot 场景仍不划算**（16 位面积 +6.3%/深度 +57%，32 位面积 −5.6% 但深度 +109%，接入 VDotCore 后整体面积仅省 ~1% 而关键路径翻倍，见 2.4 §9），面积优化方向调整为**乘法器资源共享**（2.4 §10）。

## 5. 微架构总览

```
                            ┌──────────────────────────┐
     vs1[128] ─────────────▶│       数据切分/解码      │
     vs2[128] ─────────────▶│   (sew, vl, vm, vstart) │
     vdOld[128] ───────────▶│                            │
     sew / vl / vm ───────▶│                          │
                            └────────────┬─────────────┘
                                         │
                                         ▼
                            ┌──────────────────────────┐
                            │   乘法器组（VDotCore）    │
                            │  e8:  Booth 8×8      ×16 │
                            │ e16: Chisel 原生 16×16 ×8│
                            │ e32: Chisel 原生 32×32 ×4│
                            └────────────┬─────────────┘
                                         │
                                         ▼
                            ┌──────────────────────────┐
                            │  归约累加（符号扩展）      │

                            └────────────┬─────────────┘
                                         │
                                         ▼
                                  vd[128] / vxsat
```

> **v1.4 结构变更（读此图必看）**：上图是 **v1.2 的 VDotCore 结构**，其"乘法器组 + 归约"仅 **e32 路径**仍在最终交付中使用。v1.4 起 **e8 / e16 由 K07（BWFastTop）整模块承担**——e8 走 BW8 部分积 + 计数树（§7.1b），e16 走同一模块两笔（§7.3b），归约在 K07 内部完成（§8.3），不再经过图中的"乘法器组 / 归约累加"两级。图中 `e8: Booth 8×8 ×16` 与 `e16: Chisel 原生 ×8` 两行**已废弃**。
>
> 最终通路为：`VDotFu`（sew 分流）→ E8/E16: `BWFastTop`(K07) ｜ E32: `VDotCore`（§10.1）。

### 5.1 两阶段执行模型

- **阶段 1（第 1 拍）**：按 `sew` 进行元素切分；对每个元素执行有符号乘法（e8 走 Booth、e16/e32 走 Chisel 原生乘法器）。
  > **v1.4 变更**：e8 已改 K07 的 BW8 计数树（§7.1b），e16 改 K07 两笔（§7.3b）；上述"e8 走 Booth、e16 走原生"仅适用于 e32 路径与原版 VDotCore 记录。
- **阶段 2（第 2 拍）**：符号扩展归约求和；与 `vdOld[31:0]` 累加；检测 `vxsat`；生成 `vd[31:0]` 结果。
  > **v1.4 变更**：e8/e16 走 K07 时归约在其计数树内完成、**无 vxsat**（§8.3、§9.1）。

### 5.2 流水特性

两拍之间插入寄存器，形成典型的 `piped` 流水结构；在 `piped = true` 时，第 `N+1` 条指令可在第 2 拍完成后立即进入第 1 拍，延迟被流水层叠掩盖，维持 back-to-back 发射能力。

### 5.3 设计意图

该微架构按"先并行乘法、再符号扩展归约、最后写回结果"的思路组织：

1. 先保证三种精度（e8/e16/e32）都能被统一数据通路处理；
2. 再在归约阶段以符号扩展保证负元素乘积累加正确；
3. 最终以最小控制开销完成 `mode / vl / mask / vxsat` 等约束处理。

## 6. 数据切分（SEW 解码）

按 `sew` 将 128 位源数据切分为元素组（VDotCore.scala 数据切分段）：

| sew | 元素位宽 | 元素数 | 切分逻辑 |
|---|---|---|---|
| `00` | 8 | 16 | `vs1(8i+7, 8i)`，i=0..15 |
| `01` | 16 | 8 | `vs1(16i+15, 16i)`，i=0..7 |
| `10` | 32 | 4 | `vs1(32i+31, 32i)`，i=0..3 |

切分后的元素按**有符号**送入乘法器组（`asSInt`）。三种精度的乘法器组**全部实例化**，由 `MuxLookup(sew)` 选择归约结果（`dot128`），正确性优先；工程化可改为按 sew 共享乘法器组（§12 面积讨论）。

> **v1.4 变更**：e8/e16 不再实例化上述 VDotCore 乘法器组，改由 K07 承担（§7.1b、§7.3b）；本段描述的是 e32 路径与原版记录。

## 7. 乘法器组与归约（微架构核心）

> **v1.4 结构变更总览**：本章 §7.1–§7.4 描述原版 VDotCore 的乘法器组与归约（v1.0–v1.3）。v1.4 起，**e8 与 e16 改由 K07 整模块（BWFastTop）承担**（见 §7.1b、§7.3b、§8.3），原 VDotCore 的乘法器组**仅 e32 路径继续使用**。原方案内容保留原文并标注废弃，作为演进记录。

**K07 选型依据（48 版统一综合比较）**：阶段二前期构建 48 个候选实现（Booth / Karatsuba / CSA 压缩树 / 字节级流水等路线），统一约束下逐个做 Yosys 通用门级综合（无标准单元库，只报结构指标）。K07 在"结构代价–逻辑深度–可集成性"维度胜出：

| 指标 | K07（PASS_RTL_GENERIC） | 口径 |
|---|---|---|
| 组合单元数 | 11,454 | Yosys 通用门级（抽象 cell 数） |
| 寄存器位数 | 621 | 含流水/握手寄存器 |
| 逻辑深度 | 65 | Bit.t 抽象门级深度（非 ps/FO4） |
| E8 延迟 / II | 1 拍 / 1 拍 | 模块级（无停顿时） |
| RTL SHA256 | `6860564c…` | 独立模块版本 |

> **边界声明**：以上为结构指标（通用门计数与抽象深度），只用于候选之间的相对比较，**不直接换算成面积、MHz 或功耗**。K07 的真实面积与时序已在 ASAP7 RVT TT 流程下实测（671.18 µm²；E8 1759.5 ps、E16 1737.0 ps、动态 2128.0 ps），见 §11.3、§12.1 与 `docs/stage3/3.3-延迟加速比分析.md` §一。
>
> **语义边界**：K07 只是计算内核替换，**指令语义与 §3 完全一致**——编码（§2）、vl/mask 规则、边界行为（§3.3）、与 NEMU 的契约（§3.4）均不变；§4 的对标基线（RVV `vmul.vv` + `vredsum.vs` 两条指令组合）亦不变。

### 7.1 Radix-4 Booth 乘法器（8×8，e8 用）——**v1.4 起已废弃**

> **状态：已废弃（2026-10 归档）**。v1.4 起 e8 主路改由 K07 的 BW8 部分积生成 + 计数树压缩承担（见 §7.1b）。本节保留 Booth 实现与符号补偿细节，作为演进记录与 e8 早期验证依据；`BoothMultiplier(8)` 类仍在 `VDotCore.scala` 中，但已不在 e8 主通路上（e32 路径也不使用 Booth）。

实现：`BoothMultiplier(n)`（VDotCore.scala），n=8 为 e8 基元。

**原理**：每拍扫描乘数 3 个连续位（含上一组最高位形成的重叠窗口），对乘数执行 +0/+1/+2/−1/−2 五种操作，部分积数量**减半**（8 位乘法：8 个部分积 → 4 组）。

**实现要点**：
1. **符号扩展**：被乘数统一扩展至 `2n+2` 位中间位宽（`w = 2n+2`），`2a` 为 `w+1` 位，保证负项取反不错位；
2. **负项修正**：`−a` / `−2a` 先按位取反，随后 `+1` 修正位**单独累加**（`raw +& Mux(isNeg, 1, 0)`），完成补码取负；
3. **窗口合法**：`bExt = Cat(sign, b, 0)` 扩展为 `n+2` 位，最大窗口上界 `2·ceil(n/2) ≤ n+1`，索引不越界；
4. **移位求和**：第 i 组部分积左移 `2i` 位后逐级相加，截取低 `2n` 位。

**收益**：部分积 8→4，加法树规模减半，关键路径缩短。实测 e8 全部用例正确（正 136 / 负 -136 / 边界 2032 / vl=4→10）。

### 7.1b K07 的 E8 计数树点积（**最终设计，替代 §7.1**）

K07 是"128 位输入–32 位结果"的独立 Decoupled 模块（`FastRequest`/`FastResponse` + `flush`），e8 实现如下：

1. **部分积生成**：16 对 8 位元素，每组 4 对由 **BW8 部分积生成器**产生部分积（`8×8` 有符号乘的部分积直接展开，不做 Booth 重编码）；
2. **组内压缩**：每组的 4 个部分积用 **carry-save 两行**（Q3 配置为三行）表示，**不先形成二进制组和**，避免四次串行进位；
3. **四组等权合并**：四组部分积按权重对齐后进入**计数树 / 压缩树**，经最终加法器输出 32 位结果（`vdOld + Σ(a_i·b_i)`）；
4. **压缩结构**：S02（7:3 精确混合候选）+ S03（15:4 同类候选）+ S04（有界两计数器前瞻调度）+ S06（合并 BW 高位符号补偿常量）+ S07（三来源 one-hot 字节路由）。S02/S03 为自行推导的精确压缩结构，S04 是保守 FA 深度的有界调度，非论文低延迟方程的逐式复现；
5. **时序**：正常无停顿时**组合延迟 1 拍、启动间隔 1 拍**（`out.ready` 恒真）。

> 与 §7.1 的 Booth 方案对比：Booth 把 8 个部分积压到 4 组再进加法树；K07 直接用 BW8 部分积 + 组内 carry-save 两行 + 计数树，**省掉 Booth 重编码与符号修正逻辑**，代价是部分积数量多于 Booth。48 版统一结构综合中该结构胜出（§7 开头的选型表）。

### 7.2 乘法器选型修正：Karatsuba → Chisel 原生乘法器（e16/e32）——**e16 部分已废弃**

> **状态（v1.4 后）**：本节结论对 **e32 仍然有效**（e32 继续用 Chisel 原生 `32×32`，见 §7.3b）。**e16 已改为 K07 两笔**（见 §7.3b），不再走本节的原生 `16×16` 路径。下面的 Karatsuba 缺陷记录与原生乘法器论证保留，作为 e32 路径的依据与演进记录。

**初版方案**：e16/e32 采用 **Karatsuba 位分解**，递归到 8 位 Booth 基元，复用 8×8 乘法器组以压缩面积：

```
(a·2^h + b)(c·2^h + d) = ac·2^2h + [(a+b)(c+d) − ac − bd]·2^h + bd
                            ↑ 3 个子乘法（替代 4 个）
```

**验证发现（v1.1 修正）**：`Karatsuba.signed` 在 **32 位负数路径**存在位宽截断缺陷——实测 `-3 × 2` 输出 `0xffffff583837fff8`（应为 `-6 = 0xfffffffffffffffa`），e32 混合用例 4 个乘积全部错误（-1184308404 ≠ -128）。用 Python 按 Chisel 语义（补码左移 + 固定位宽截断）精确复现了该缺陷，定位在递归乘法的符号位扩展与截断逻辑。

**最终方案**：e16/e32 改用 **Chisel 原生有符号乘法器**（`io.vs1(...).asSInt * io.vs2(...).asSInt`）：

- 逻辑等价（有符号乘法，乘积 2×SEW 位精确）；
- 正确性由 Chisel/综合工具保证，规避自研乘法器的位宽风险；
- 面积代价可接受：e16 仅 8 个 16×16、e32 仅 4 个 32×32 乘法器；
- 实测 e16（36）、e32 正数（10）、e32 混合（-128）全部正确。

> **工程化方向**：2.4 已验证**修复版 Karatsuba**（低位零扩展、和变宽、交叉项留符号）在 vdot 场景仍不划算——16 位面积 +6.3%/深度 +57%，32 位面积 −5.6% 但深度 +109%，接入 VDotCore 后整体面积仅省 ~1% 而关键路径翻倍（见 2.4 §9）。面积优化方向调整为**乘法器资源共享**（8×8 基元池 + 符号修正 + Wallace 拼接，见 2.4 §10）。当前版本以**功能正确性优先**。

实现：VDotCore.scala 归约段（`reduceCSA` + 单次 CPA）。

**v1.2 优化**：初版将所有乘积符号扩展至 **128 位链式归约**（`reduce(_ +& _)`）后再与 vdOld 累加，高位冗余且存在两条进位链。新版按"完整点积和（对数上界）+ 32 位 vdOld"确定各档最小位宽，并将 vdOld 作为归约操作数直接融入 CSA 压缩树，全通路只保留一次进位传播加法（CPA）：

```
W8  = 33   # 16×16bit 乘积完整有符号和 = 20bit，+ vdOld[31:0] → 33bit
W16 = 36   # 8×32bit 乘积完整有符号和 = 35bit，+ vdOld[31:0] → 36bit
W32 = 67   # 4×64bit 乘积完整有符号和 = 66bit，+ vdOld[31:0] → 67bit

old = Cat(Fill(W-32, vdOld[31]), vdOld[31:0])        # vdOld[31:0] 符号扩展为归约操作数
(s, c) = reduceCSA(products.pad(W) :+ old)           # 3→2 逐级压缩至 (sum, carry)
full   = s +& c                                      # 唯一一次 CPA
result = full[31:0]                                  # 截断到 32 位标量
```

> **历史修正（v1.1，保留）**：初版用**零扩展**累加，负数乘积（如 `-1 = 0xFFFF`）被当作正数 65535，导致 e8 负数用例输出 `1048440` 而非 `-136`。改为**符号扩展**后正确。

> **vl 掩码上移（v1.2）**：初版在内核内 `Mux(i < vl, prod, 0)` 掩码，与外壳 VDotFu stage0 的 operand gating（按 `(i<vl)&&(vm||mask(i))` 清零乘法器输入）功能冗余。新版删除内核内掩码，元素级门控统一由外壳完成（减少约 128 位 × 3 档 Mux 面积）。

## 8. 归约加法结构（v1.2 Fused ReduceAcc / K07 归约并列）

### 8.1 归约实现（e32 路径主通路；e8/e16 见 §8.3）

各档乘积（按 SEW 符号扩展至 W8/W16/W32）与 `vdOld[31:0]`（符号扩展）一起送入 `reduceCSA`：**每级 3→2（CSA）逐级压缩**，最终得到 `(sum, carry)` 两个操作数，再由 `full = s +& c` **唯一一次进位传播加法**完成归约累加。CSA 的 `carry` 已左移 1 位（权重 2），直接相加即正确。

- 加法深度：17/9/5 个操作数 → CSA 级数 log3/2 压缩，末级单 CPA；
- 相比初版"128 位链式 `reduce(_+&_)` + 二次累加"：位宽降至 33/36/67，且消除第二条进位链（关键路径 ≈ 乘法器 → CSA 树 → 单 CPA）。

### 8.2 参考：CSA/Wallace 结构（保留类）

- **CSA**：`sum = a ^ b ^ c`，`carry = Cat(majority(a,b,c), 0)`（carry 已左移 1 位，权重 2）；
- **CSATree**：Wallace 风格递归 3→2 压缩（直接输出最终和的参考实现）；
- 两类的类定义保留在 VDotCore.scala 中（CSA 被 reduceCSA 复用；CSATree 为参考）。

> **v1.2 说明**：初版主通路为 128 位链式加法（`reduce(_+&_)`），CSATree 仅作备选。v1.2 已将主通路改为 CSA 压缩 + 单 CPA（即初版"备选方案"的工程化落地），链式加法代码已移除。

### 8.3 K07 的归约结构（**e8/e16 最终路径，替代 §8.1**）

K07 不复用 §8.1 的 Fused ReduceAcc（把 `vdOld` 作为归约操作数送进 CSA 树），而是把归约做在**计数树内部**：

- **组内**：每 4 对元素的部分积先用 carry-save 两行（Q3 为三行）表示，不形成二进制组和；
- **组间**：四组部分积按等权合并进计数树 / 压缩树（S02 7:3 + S03 15:4 + S04 有界前瞻调度）；
- **vdOld**：作为额外加数进入最终加法级（`vdOld + Σ(a·b)` 一次成型）；
- **输出**：32 位截断，模 2³²（**无 vxsat**，见 §9.1）。

> 与 §8.1 的差别：§8.1 是"先算完整点积、再与 vdOld 做一次 CPA"；K07 在压缩树里一并处理，省掉一次独立进位链，但压缩树规模随元素数增长（e16 两笔即为此代价，§7.3b）。

#### e16 两笔的归约拼接

第 1 笔产出 `sum(1..4)` 暂存为第 2 笔的 `vdOld`，第 2 笔把 `sum(5..8)` 叠加其上并一次写回——**不引入额外的 32 位加法器**，拼接发生在 K07 的 `vdOld` 输入端（`io_out_bits.result → io_in_bits.vdOld`，寄存器直连，非组合环）。

## 9. 累加与溢出（v1.2：Fused 单 CPA + 32 位溢出检测）——e32 路径，K07 见 §9.1

实现：VDotCore.scala 累加段 + VDotFu.scala（slotMask / tail）。

```
old8  = Cat(Fill(W8-32,  vdOld[31]), vdOld[31:0])      # vdOld[31:0] 符号扩展为归约操作数
(s, c)  = reduceCSA(products8 :+ old8)                  # 与乘积一起 3→2 压缩
full    = s +& c                                        # 唯一一次 CPA（Fused Accumulator）
vxsat   = full(31) ^ full(32)                           # bit32 须为 bit31 的符号扩展，否则截断改变符号
result  = full[31:0]                                    # 截断到 32 位标量
```

- **累加语义**：`vd = dot + vd_old`，`vd_old[31:0]` 作为归约操作数直接进 CSA（**Fused Accumulator**），全通路只做一次进位传播加法；
- **溢出策略**：截断 + vxsat 置位。`vxsat = full(31) ^ full(32)`：full 落在 [−2^31, 2^31−1] 时 bit32 恒等于 bit31（符号扩展），否则超界。
  > **v1.2 修正**：初版 `vxsat = acc(128)`（128 位加法溢出位）在当前位宽下几乎永不触发，语义错误；且首版"高位全 0/全 1"判定对 2^31（bit31=1、bit32.. 全 0）漏报。回归用例 13（vd=0x7FFFFFFF + 1 → 0x80000000）暴露后改为 `full(31) ^ full(32)`。
- **slotMask（VDotFu）**：固定 `0x00000000ffffffff`——vdot 结果统一写 `vd[31:0]`，高 96 位由尾策略处理（`tailVd = (oldVd & ~slotMask) | (redVd & slotMask)`，ta=0 保留旧值；ta=1 全 1）；
- **已知限制**：点积和截断到 32 位标量。若 e16/e32 的点积和超出 32 位有符号范围（|sum| ≥ 2^31），高位被截断、仅 vxsat 置位。2.3 测试用例（e16=36、e32=-128、e32 边界=2^31-1、e32 溢出=0x80000000）验证截断与溢出检测。

### 9.1 K07 路径的累加与溢出（**e8/e16 最终路径**）

> 本节与上文正文（e32 路径）并列：上文描述 `VDotCore` 的溢出检测，本节描述 K07 的行为差异。

- **累加**：K07 在压缩树内完成 `vdOld + Σ(a·b)`，输出截断到 32 位，模 2³²（§8.3）；
- **饱和/vxsat**：K07 **不产生 vxsat、不实现饱和**。e8/e16 走 K07 时整核侧直接置 `false.B`；
- **与 NEMU 口径**：NEMU 的 vdot 扩展不写 `vcsr`/`vxsat`，与 K07 一致；
- **e32 仍走 §9 主体**：`vxsat = full(31) ^ full(32)` 检测保留，但香山整核 `VPUSubModule` 的 vxsat 写回链路当前被注释，e32 的溢出标志实际未写回 CSR（`3.9` 与 `2.3` §5 均已声明）。

### 10.4 外壳要点（VDotFu）

- **输入锁存**：9 处 RegEnable 在 S1 锁存 `vs1/vs2/vdOld/vl/sew/vm/ta/vstart` 等，对齐 Reduction.scala 的 `fire_reg_s1 = RegNext(fire)` 范式；
- **执行门控**：`exec = fire && vstart < vl`（vstart ≥ vl 不执行）；
- **结果写回**：`tailOut = Mux(vl===0, oldVd, Mux(ta, tailOne, tailVd))`，slotMask 固定低 32 位；
- **vxsat 输出**：`io.out.vxsat := dotSat && exec`。

**v1.4 增补（K07 路径外壳要点）**：

- **输入必须接当前指令原始输入**：`vs1_r/vs2_r/vsew_r` 等是 `RegEnable`，**fire 沿才更新**；K07 若接锁存值会取到上一条指令的数据（首轮整核报 `v2_low 0x00 vs 0x88`）。修复：K07 输入全部接 `io.in.bits`（vs1/vs2 即时按 `vl/vm/mask` 清零、vdOld/sew 取当前指令），valid 判定用 `io.in.bits.vdType(1,0) === 0.U`。原版 `VDotCore` 纯组合、S2（fire+1）采样时锁存值已更新，不受影响。
- **模式感知归零**：E8 用 16 个字节 lane 归零；E16 用**低 64 位的 4 个半字 lane**归零（两笔各一次）；K07 的 `mask` 恒 `0xFFFF`。
- **握手**：`out.ready` 恒真（香山 out 无 ready）→ valid 一拍即清，E8 II=1；`flush=false.B`；tag 置 0。
- **S2 对齐**：新增 `k07E8ResultS2`（S2 沿寄存器，`VDotFu.scala:211`：`RegEnable(k07.io.io_out_bits_result, k07.io.io_out_valid && !pass2S2)`）承载 K07 组合输出，供 `opcodeS2` 采样——这是仓库 vendored 副本 V-A 与早期 V-B 的关键差异（V-B 无此寄存器，背靠背取到错误 `old_vd`）。
- **E16 两笔状态机**：`pass2Fire`/`pass2S2` 控制第 2 笔发射与采样，`vs1HiS1`/`vs2HiS1` 各 64 位暂存第 2 笔输入；`pass2Conflict` 为防御性断言（背靠背两条 e16 相邻时检查），MinimalConfig 3 项 b2b 已验证未触发。

## 11. 时序与流水线（含 K07 双模式）

### 11.1 两拍划分

**e32 路径（原版 VDotCore）**：

| 拍 | 完成内容 |
|---|---|
| 第 1 拍 | 数据切分 → 乘法器组（Booth / Chisel 原生）→ 乘积与 vdOld 符号扩展入 CSA 树压缩 |
| 第 2 拍 | 单次 CPA（`full = s +& c`）→ vxsat 检测 → 结果截断打包 |

**e8 路径（K07，v1.4）**：

| 拍 | 完成内容 |
|---|---|
| 第 1 拍（组合） | BW8 部分积生成 → 组内 carry-save 两行 → 四组等权合并进计数树 → 32 位结果（组合逻辑，单拍内完成） |
| 第 2 拍（S2 采样） | `k07E8ResultS2` 在 S2 沿锁存，`opcodeS2` 采样 → 写回；无 CPA 级 |

**e16 路径（K07 两笔，v1.4）**：

| 时刻 | 动作 |
|---|---|
| t0 | 发第 1 笔（元素 0–3，`mask[3:0]`，`vdOld=old_vd`），结果不回写 |
| t1 | 发第 2 笔（元素 4–7 下移，`mask[7:4]`，`vdOld=第 1 笔结果`） |
| t2 | 采第 2 笔结果并唯一一次写回 |

> 两笔正好落在原 `CertainLatency(2)` 窗口内（t2 即原 `opcodeS2` 采样沿），`VipuCfg.latency` 仍为 `CertainLatency(2)`，**`VIAlu`/`VipuCfg` 均未改动**。

### 11.2 back-to-back 发射

- `piped = true` + `latency = CertainLatency(2)`：发射队列允许背靠背发射；
- 外壳寄存器级（VDotFu 的 S1 锁存）承担流水切分：第 N 条指令在第 2 拍累加时，第 N+1 条已进入第 1 拍；
- **结果**：延迟 2 拍被流水隐藏，吞吐 1 条/周期。

**K07 路径（v1.4）**：

- **E8**：K07 `out.ready` 恒真、valid 一拍即清，**II=1**；`k07E8ResultS2` 保证背靠背时第 N+1 条不会读到第 N 条的 `old_vd`（V-B 缺此寄存器即在此处出错）。
- **E16**：两笔在同一指令内完成，不跨指令占拍，**指令级 II 仍为 1**；但第 2 笔依赖第 1 笔结果，内部为串行两拍。
- **背靠背验证**：MinimalConfig 下 3 项相邻 e16（PC 差 4 字节）测试通过，`pass2Conflict` 未触发（防御性断言）；`KunminghuV2Config` 下尚未复测（见 §13.4 未覆盖项）。

### 11.3 K07 交付版的分模式时序（ASAP7 RVT TT，reg→reg）

| 模式 | arrival | FO4 | 最慢路径起点 |
|---|---:|---:|---|
| **E8** | **1759.5 ps** | **98.0** | `io_in_bits_mask[7]` |
| **E16** | **1737.0 ps** | **96.7** | `io_in_bits_mask[3]` |
| 动态（模式选择） | 2128.0 ps | 118.5 | `q_e16` |

读法：

- **E8 与 E16 各自的最慢路径都在 1.74–1.76 ns 量级，两者相当**——E16 每笔只算 4 对，算术量小于 E8 的 16 对，所以不构成瓶颈。
- **E16 的时序不是设计目标**：它只为满足可扩展性（同一套 16 个 BW8 覆盖 e16 的 8 个元素），由 `VDotFu` 发两笔完成。
- 真正的代价来自「要同时支持两种模式」：动态模式 2128.0 ps，最慢路径起点是 `q_e16` 模式寄存器，经 6 级以上 `BUFx2` 扇出进入数据通路选择——这是**控制路径**，不是 E16 的算术路径。
- 2128.0 ps 对应约 470 MHz；若目标频率 2–3 GHz，K07 与原生一样都需流水化。

测量条件与同口径基线对照见 `docs/stage3/3.3-延迟加速比分析.md` §一。
