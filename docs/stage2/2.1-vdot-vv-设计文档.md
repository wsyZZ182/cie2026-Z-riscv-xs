## 1. 概述

vdot.vv 是一条**自定义向量归约指令**：单条指令完成"逐元素乘法 → 全向量归约求和 → 累加到目标寄存器"三个操作，将 RVV 基线中 `vmul.vv` + `vredsum.vs` 两条指令（含一次额外向量寄存器写回）压缩为一条指令。

| 对比项 | 基线（vmul.vv + vredsum.vs） | vdot.vv |
|---|---|---|
| 指令数 | 2 | 1 |
| 中间写回 | 一次 vd 写回 | 无 |
| 语义 | 逐元素乘，再单独归约 | 乘+归约+累加融合 |

本指令支持 e8 / e16 / e32 三种精度，可配置有效元素数（vl），并携带定点溢出标志（vxsat），面向嵌入式 AI 推理等"内积密集"场景。

## 2. 指令编码

vdot.vv 采用 RVV 1.0 的 **OP-V** 指令格式，编码位于 `OPMVV` 子空间（`funct3 = 100`）。与 RVV 基础归约指令同属一组，其中 `vredsum / vredand / vredor / vredxor` 已占用 `funct6 = 000000`–`000011`；在该归约组之后，`000100` 为空闲编码，且不与 RVV 1.0 后续扩展（如 `Zvbb`、`Zvbc`）冲突，因此选用该值作为本指令的 `funct6`。

### 2.1 编码格式

```
31                26 25 24              20 19              15 14        12 11             7 6             0
┌──────────────────┬──┬──────────────────┬──────────────────┬───────────┬──────────────────┬──────────────┐
│      funct6      │vm│       vs2        │       vs1        │  funct3   │       vd         │    opcode    │
│      000100      │  │                  │                  │   100     │                  │   1010111    │
└──────────────────┴──┴──────────────────┴──────────────────┴───────────┴──────────────────┴──────────────┘
  vdot.vv vd, vs2, vs1, vm
```

字段说明：

- `funct6 = 000100`：本指令专用编码，位于 `OPMVV` 归约扩展区。
- `vm`：按 RVV 规范，控制掩码寄存器 `v0` 是否参与计算。
- `vs2` / `vs1`：两个参与逐元素乘法的源向量寄存器。
- `vd`：目标寄存器，结果写回到 `vd[0]`，其余槽按尾策略处理。
- `funct3 = 100`：统一归约型 `OPMVV` 指令位域。
- `opcode = 1010111`：RVV `OP-V` 指令编码。

### 2.2 编码分配

```
OPMVV (funct3 = 100)
├── 000000 : vredsum
├── 000001 : vredand
├── 000010 : vredor
├── 000011 : vredxor
├── 000100 : vdot.vv   ← 采用编码
├── 010000 : vrxunary0
├── 010010 : vxunary0
├── 010100 : vmunary0
└── 其余 : 保留 / 扩展
```

因此，vdot.vv 与 RVV 现有归约指令保持同一编码族，且不会破坏已有 `vred*` 语义，也不与后续 `OPMVV` 扩展保留位冲突，满足“新增指令、最小侵入、兼容性优先”的编码策略。

## 3. 指令语义

### 3.1 伪代码

```
vdot.vv vd, vs2, vs1, vm:
  for i in 0 .. vl-1:
    if vm == 0 and v0[i] == 0: skip        # 掩码元素跳过
    acc += sign_ext(vs1[i], SEW) * sign_ext(vs2[i], SEW)   # 乘积精确（2×SEW 位）
  vd[0] = acc + vd_old[0]                   # 累加旧值，截断到目标槽宽
  if 累加溢出: vxsat = 1                    # 当前策略：置位但不饱和
  vd[1:] = 0                                 # 其余槽由 Mgu 按尾策略处理
```

### 3.2 三种精度行为

| SEW（vsew 编码） | 元素数（VLEN=128） | 乘积宽度 | 累加目标槽 | vd 其余槽 |
|---|---|---|---|---|
| e8（`00`） | 16 | 16 位（精确） | vd[31:0] | 置 0 |
| e16（`01`） | 8 | 32 位（精确） | vd[63:0] | 置 0 |
| e32（`10`） | 4 | 64 位（精确） | vd[127:0] | — |

### 3.3 边界规则

1. **vl 掩码**：仅 `i < vl` 的元素参与归约，其余元素贡献 0（由内核掩码实现，见 §7.4）。
2. **尾元素**：`i ≥ vl` 的 vd 槽按 RVV 尾策略（vta）由 Mgu 处理；本内核输出 0。
3. **溢出**：乘积不溢出（宽度 2×SEW 精确），仅**累加阶段**可能溢出。当前策略为**截断 + vxsat 置位**（VDotCore 中 `acc(128)` 为溢出位）；如需饱和语义可在累加器扩展（§9 有说明）。
4. **vstart / 掩码**：按 RVV 规范由外壳（VecPipedFuncUnit + Mgu）处理，内核接口不含 vstart（对齐 Reduction.scala 的归约范式）。

### 3.4 与阶段三 NEMU 的契约

本文档 §3.1–§3.3 语义是阶段三 NEMU 参考实现（`vdot.vv` 模拟逻辑）的**唯一依据**。NEMU 端必须实现：三精度符号乘法、vl 掩码、与 vd[0] 累加、截断 + vxsat。

## 4. 设计目标与约束

### 4.1 对标基线

参考实现 nanhu-vdot（arXiv 2409.00661）采用**固定 8-bit 乘法器阵列**（8 路 8×8 乘法器 + 7 个加法器，输出 64 位），仅支持单一精度。本设计的目标是**一套乘法器组覆盖 e8/e16/e32 三种精度**，形成"固定 8-bit 基线 vs 多精度复用"的对比叙事。

### 4.2 设计约束

| 约束 | 取值 | 依据 |
|---|---|---|
| VLEN | 128 位 | 香山向量寄存器位宽 |
| SEW | e8 / e16 / e32 | 比赛 2.3 测试要求（正/负/边界） |
| 结果精度 | 精确（乘积 2×SEW 位） | 边界值测试需精确比对 |
| 延迟 | 2 拍（CertainLatency(2)） | 乘+树+累加两拍完成 |
| 吞吐 | back-to-back，1 条/周期 | piped=true + 流水累加器 |

### 4.3 优化边界（算法选型）

> **定理（下界）**：精确计算任意两个长度 K 的运行时向量的点积，至少需要 K 次乘法。优化空间只在面积、延迟、吞吐三个维度。

经调研，Fast Inner Product（FIP，Winograd 1968）及 Free-Pipelined FIP（arXiv 2311.12224）等"减乘法"算法依赖多输出间的中间结果复用（α/β 项），仅适用于矩阵乘法/脉动阵列场景；位层 MAC、分布式算术、查表法分别依赖权重稀疏性、固定系数等前提，均与 vdot.vv 的单指令、运行时操作数、精确计算约束不兼容。单条点积的乘法次数下界为 K，本设计将优化集中于微架构层：**Radix-4 Booth 编码乘法器**减半部分积；**Wallace 进位保存压缩树**将加法深度从 4 级压至 3 级；**流水化累加器**实现 back-to-back 发射。e32 模式采用 **Karatsuba 位分解**，以 8×8 乘法器组实现 32×32 乘法，在保证精确性的前提下显著降低面积，相比 nanhu-vdot 固定 8-bit 乘法器阵列具备多精度复用优势。

## 5. 微架构总览

```
                            ┌────────────────────────────┐
     vs1[128] ─────────────▶│       数据切分/解码       │
     vs2[128] ─────────────▶│   (sew, vl, vm, vstart)  │
     vdOld[128] ───────────▶│                            │
     sew / vl / vm ───────▶│                            │
                            └────────────┬─────────────┘
                                         │
                                         ▼
                            ┌────────────────────────────┐
                            │   乘法器组（VDotCore）     │
                            │  e8: Booth8×8 ×16         │
                            │  e16: Karatsuba16 ×8      │
                            │  e32: Karatsuba32 ×4      │
                            └────────────┬─────────────┘
                                         │
                                         ▼
                            ┌────────────────────────────┐
                            │     CSA / Wallace 树       │
                            │  逐元素乘积汇总 & 压缩     │
                            │      深度约 3 级           │
                            └────────────┬─────────────┘
                                         │
                                         ▼
                            ┌────────────────────────────┐
                            │        累加器/归约         │
                            │  + vdOld[0] + vxsat 检测  │
                            │  128-bit 精确累加         │
                            └────────────┬─────────────┘
                                         │
                                         ▼
                            ┌────────────────────────────┐
                            │       结果打包输出         │
                            │  vd[0] = 累加结果         │
                            │  其余槽按 tail / mask 处理 │
                            └────────────┬─────────────┘
                                         │
                                         ▼
                                  vd[128] / vxsat
```

### 5.1 两阶段执行模型

- **阶段 1（第 1 拍）**：按 `sew` 进行元素切分；对每个元素执行有符号乘法；乘积进入 `CSA/Wallace` 树完成中间压缩。
- **阶段 2（第 2 拍）**：对压缩结果做最终加法；与 `vdOld[0]` 累加；检测 `vxsat`；然后生成 `vd[0]` 和尾元素处理结果。

### 5.2 流水特性

两拍之间插入寄存器，形成典型的 `piped` 流水结构；在 `piped = true` 时，第 `N+1` 条指令可在第 2 拍完成后立即进入第 1 拍，延迟被流水层叠掩盖，维持 back-to-back 发射能力。

### 5.3 设计意图

该微架构按“先并行乘法、再压缩与归约、最后写回结果”的思路组织：

1. 先保证三种精度（e8/e16/e32）都能被统一数据通路处理；
2. 再在乘积聚合阶段尽量压低加法树深度；
3. 最终以最小控制开销完成 `mode / vl / mask / vxsat` 等约束处理。

## 6. 数据切分（SEW 解码）

按 `sew` 将 128 位源数据切分为元素组：

| sew | 元素位宽 | 元素数 | 切分逻辑（VDotCore 第 197–220 行） |
|---|---|---|---|
| `00` | 8 | 16 | `vs1(8i+7, 8i)`，i=0..15 |
| `01` | 16 | 8 | `vs1(16i+15, 16i)`，i=0..7 |
| `10` | 32 | 4 | `vs1(32i+31, 32i)`，i=0..3 |

切分后的元素按**有符号**送入乘法器组（`asSInt`）。三种精度的乘法器组**全部实例化**，由 `MuxLookup(sew)` 选择归约结果（VDotCore 第 227–231 行），正确性优先；工程化可改为按 sew 共享乘法器组（§12 面积讨论）。

## 7. 乘法器组（微架构核心）

### 7.1 Radix-4 Booth 乘法器（8×8 基元）

实现：`BoothMultiplier(n)`（VDotCore 第 24–58 行），n=8 为基元。

**原理**：每拍扫描乘数 3 个连续位（含上一组最高位形成的重叠窗口），对乘数执行 +0/+1/+2/−1/−2 五种操作，部分积数量**减半**（8 位乘法：8 个部分积 → 4 组）。

**实现要点**（修复版，评审重点）：
1. **符号扩展**：被乘数统一扩展至 `2n+2` 位中间位宽（`w = 2n+2`），`2a` 为 `w+1` 位，保证负项取反不错位；
2. **负项修正**：`−a` / `−2a` 先按位取反，随后 `+1` 修正位**单独累加**（第 54 行 `raw +& Mux(isNeg, 1, 0)`），完成补码取负；
3. **窗口合法**：`bExt = Cat(sign, b, 0)` 扩展为 `n+2` 位，最大窗口上界 `2·ceil(n/2) ≤ n+1`，索引不越界；
4. **移位求和**：第 i 组部分积左移 `2i` 位后逐级相加，截取低 `2n` 位。

**收益**：部分积 8→4，加法树规模减半，关键路径缩短。

### 7.2 Karatsuba 位分解（16×16 / 32×32）

实现：`Karatsuba`（VDotCore 第 121–165 行），`KaratsubaMultiplier(n)` 封装（第 167–174 行）。

**原理**：m×m 乘法分解为 3 个 (m/2)×(m/2) 子乘法 + 3 次加减法，替代朴素 4 个子乘法：

```
(a·2^h + b)(c·2^h + d) = ac·2^2h + [(a+b)(c+d) − ac − bd]·2^h + bd
                            ↑ 3 个子乘法
```

**关键性质**：不依赖点积长度、不依赖矩阵结构、操作数任意——**单条 vdot 指令直接成立**。

**有符号拆法**（修复版实现，第 144–164 行）：
- x1 取**有符号高位**、x0 取**无符号低位**；
- `x1 + x0` 需 `h+2` 位（第 156 行 `pad(h+2)`），防溢出；
- z1（高位积）有符号、z0（低位积）无符号、z2 = (x1+x0)(y1+y0) − z1 − z0 有符号；
- 递归到 8 位时落到 Booth 基元（`n ≤ 8` 终止条件）。

**收益**：e32 元素用 8×8 乘法器组实现 32×32 乘法（面积 4 个 8×8 乘法器 vs 朴素 16 个 8×8 等价逻辑）；e16 收益次之。e8 因加减法开销占比高，直接用 Booth 基元。

### 7.3 乘法器组账目

| 精度 | 乘法器 | 数量 | 8×8 Booth 基元展开数 |
|---|---|---|---|
| e8 | `BoothMultiplier(8)` | 16 | 16 |
| e16 | `KaratsubaMultiplier(16)` | 8 | 8×3 = 24 |
| e32 | `KaratsubaMultiplier(32)` | 4 | 4×9 = 36 |
| **合计** | | 28 | **76** |

> 当前实现为正确性优先的全实例化（76 个基元展开）。工程化优化：按 sew **复用**同一组乘法器（16 个 8×8 基元即可覆盖三精度，Karatsuba 递归复用），面积可降至约 1/4

### 7.4 vl 掩码与归约

实现：VDotCore 第 222–231 行。

```
sumE8  = Σ_{i<16} Mux(i < vl, Cat(0(112), prod8(i)), 0(128))   # 零扩展后累加
sumE16 = Σ_{i<8}  Mux(i < vl, Cat(0(96),  prod16(i)), 0(128))
sumE32 = Σ_{i<4}  Mux(i < vl, Cat(0(64),  prod32(i)), 0(128))
dot128 = MuxLookup(sew)(sumE8, sumE16, sumE32)
```

- 乘积为 SInt（16/32/64 位），`asUInt` 后零扩展至 128 位再累加——**负乘积贡献负数**（零扩展保留了补码语义，在 128 位累加器中自然处理符号）；
- `i ≥ vl` 的元素贡献 0，实现 vl 掩码。

## 8. 加法树结构（Wallace / CSA）

### 8.1 CSA（进位保存加法器）

实现：`CSA(width)`（VDotCore 第 65–75 行）。

```
sum   = a ^ b ^ c
carry = Cat(majority(a,b,c), 0)   # 已左移 1 位！权重为 2，直接相加即正确
```

**修复要点**：carry 必须左移 1 位输出（权重 2），否则丢失进位权重、结果必错。这是本设计初版的最大错误，已在修复版修正。

### 8.2 Wallace 压缩树

实现：`CSATree(numInputs, width)`（VDotCore 第 81–107 行）。

- **递归 3→2 压缩**：每 3 个操作数一组经 CSA 压缩为 2 个（和+进位），不足 3 个的原样保留，递归直至 ≤2 个；
- **末级进位传播加法器**：最终 2 个操作数 `reduce(_ +& _)` 完成进位传播；
- 中间统一宽度 `W = width + log2Ceil(numInputs) + 2`，防压缩过程溢出；
- 输出宽度 `width + log2Ceil(numInputs)`。

### 8.3 深度对比（e8 为例：16 个乘积求和）

| 方案 | 结构 | 加法器数 | 关键路径深度 |
|---|---|---|---|
| 直接二叉树 | 16→8→4→2→1 | 15 | 4 级 |
| **Wallace + CSA（本设计）** | 3→2 逐级压缩，末级 CPA | ≈15 | **≈3 级** |

CSA 每级只产生"和+进位"，不传播进位 → 每级延迟约一个全加器 → 关键路径 4 级压至 3 级，同工艺下主频提升约 25%。

## 9. 累加与溢出

实现：VDotCore 第 233–247 行。

```
oldSlot = MuxLookup(sew)(vdOld[31:0], vdOld[63:0], vdOld[127:0])   # 按 sew 取旧值槽
acc     = oldSlot +& dot128                                         # 128 位累加
vxsat   = acc(128)                                                  # 溢出位
result  = MuxLookup(sew)(Cat(0(96), acc[31:0]), Cat(0(64), acc[63:0]), acc[127:0])
```

- **累加语义**：与目标寄存器旧值累加（`vd = dot + vd_old`），对应 RVV 归约的"初始值"概念，但此处为 `vd[0]` 而非 vs1[0]；
- **溢出策略**：截断 + vxsat 置位。如需饱和语义，将末级加法改为"检测 acc(128) 后输出 0x7FFF…F / 0x8000…0"即可（工程量约 10 行，留作扩展点）；
- **结果打包**：标量结果放第一个元素槽，其余槽 0（tail 由香山 Mgu 处理，见 §10）。

## 10. 数据通路与香山集成

### 10.1 执行单元位置

当前香山源码（本作品编译通过的版本）中，向量执行单元位于 **`backend/fu/wrapper/`**（继承 `VecPipedFuncUnit`），计算内核在 **`yunsuan/`** 子模块。

```
backend/fu/wrapper/VDotU.scala   ← 新建（仿 VIMacU.scala 模板）
        │ 调用
        ▼
yunsuan/vector/vdot/VDotCore.scala   ← 本设计计算内核
```

### 10.2 外壳模板（仿 VIMacU 三段式）

```
class VDotU(cfg: FuConfig)(implicit p: Parameters) extends VecPipedFuncUnit(cfg)
```

1. **类型解码器** `VDotSrcTypeModule extends VecSrcTypeModule`：由 fuOpType 解出 vs1Type/vs2Type/vdType（符号 + vsew）。vdot 不做 widen，比 VIMacSrcTypeModule 更简单：
   ```
   vs2Type = Cat(0, vs2Sign, vsew);  vs1Type = Cat(0, vs1Sign, vsew)
   vdType  = Cat(0, vs1Sign, vsew)   # vd 与源同宽（结果在第一槽）
   illegal = false.B
   ```
2. **计算内核**：`VDotCore` 直接接收 `vs1/vs2/vdOld`（128 位）+ `sew` + `vl`，输出 `result/vxsat`。归约范式对齐 `yunsuan/vector/VectorALU/Reduction.scala`（vredsum：`fire_reg_s1 = RegNext(fire)` 流水累加）。
3. **Mgu 收尾**：按 vl/vstart/ta/ma 生成最终写回数据（tail 填充、prestart 保留、掩码清零）：
   ```
   mgu.io.in.vd     := Cat(0, result)          # 归约结果放最低槽
   mgu.io.in.oldVd  := outOldVd                # tail/prestart 用
   mgu.io.in.mask   := outSrcMask
   mgu.io.in.info.{ta,ma,vl,vstart,eew,vsew,vdIdx} := ...
   io.out.bits.res.data   := mgu.io.out.vd
   io.out.bits.res.vxsat  := (vxsat & mgu.io.out.active).orR
   ```

### 10.3 VdotCfg（注册表，仿 VimacCfg）

```scala
val VdotCfg = FuConfig(
  name = "vdot",
  fuType = FuType.vdot,
  fuGen = (p, cfg) => Module(new VDotU(cfg)(p).suggestName("Vdot")),
```

## 11. 时序与流水线

### 11.1 两拍划分

| 拍 | 完成内容 |
|---|---|
| 第 1 拍 | 数据切分 → 乘法器组（Booth/Karatsuba）→ CSA 树压缩（进位不传播） |
| 第 2 拍 | 最终进位传播 → 与 vdOld 累加 → vxsat → 结果打包 → Mgu 收尾 |

### 11.2 back-to-back 发射

- `piped = true` + `latency = CertainLatency(2)`：发射队列允许背靠背发射；
- 流水化累加器（参考 Reduction.scala 的 `fire_reg_s1 = RegNext(fire)` 范式）：第 N 条指令在第 2 拍累加时，第 N+1 条已进入第 1 拍；
- **结果**：延迟 2 拍被流水隐藏，吞吐 1 条/周期。

## 12. 面积与性能估算

| 维度 | 估算 | 说明 |
|---|---|---|
| 乘法器 | 28 个模块（16 Booth8 + 8 Karatsuba16 + 4 Karatsuba32） | 基元展开 76 个 8×8 Booth；可复用降至 16 个 |
| 加法树 | 16 输入 Wallace 树（e8） | 深度 ≈3 级 CSA |
| 关键路径 | 乘法器（Booth 4 组）→ CSA 树 3 级 → 末级 CPA → 累加 | 2 拍可收敛 |
| 对比 nanhu-vdot | 其 LUT +2.8% / FF +0.9% / BRAM 0（FPGA 数据） | 本设计多精度代价为面积复用（Karatsuba 额外加减法） |
